## 1. Why this slice exists (the disk-grounded finding it fixes)

Today the executor (`backend/tvashtr/control_plane/team_run.py`, `run_graph`) carries two hard
couplings that make "capability is authorable" impossible without this change:

- **A completion node is valid ONLY as the start node.** The completion branch is
  `if current == start_id: pm_step(...)` else **fails the run** ("unexpected non-start completion
  node … PM is the only one"). So a thinker anywhere but the root crashes.
- **The start completion is the sole writer of the spec doc every worker reads.** `pm_step` is the
  only writer of `Run.pm_document_id`; every agent node calls `read_latest_prd_step`, which RAISES
  if `pm_document_id` is unset.

Consequence: on the current templates there is **no valid capability flip** — flipping a worker
to a thinker hits the non-start-completion fail; flipping the root thinker to a worker makes
`read_latest_prd_step` raise. This slice generalizes the completion branch into a real "thinker"
node so a thinker is composable anywhere, and adds the capability toggle + the one invariant the
executor still needs (the root is a thinker).

**Decomposition that keeps the high-risk executor diff minimal (do it this way):** keep `pm_step`
**byte-identical** as the FIRST-thinker path (same signature, same `pm-llm` cost key, same
`pm-prd-v1` doc key) and add a **new, purely additive `thinker_refine_step`** for LATER thinkers.
Because the single-thinker templates (`two_node`, `review_loop`) only ever hit `pm_step`, the
three `pm-llm` checkers and every existing executor-test stub stay UNTOUCHED.

**T1 — Generic thinker in the executor (`team_run.py`).**
- Add a new recorded step `thinker_refine_step(run_id, idea, model, prompt, node_id, iteration,
  current_spec, spec_document_id) -> dict`:
  - Build the LLM prompt: `prompt + f"\n\nFeature request:\n{idea}" + f"\n\n--- CURRENT SPEC (this
    is the spec so far — produce the COMPLETE updated spec, preserving everything still needed) ---
    \n{current_spec}"`.
  - `result = complete(CompletionRequest(model=model, messages=[{"role":"user","content":prompt_full}],
    temperature=0.3, max_tokens=400))` (mirror `pm_step`'s call shape).
  - `record_cost(result, workflow_id=run_id, idempotency_key=f"{run_id}:thinker-llm:{node_id}:{iteration}")`.
  - `add_version(uuid.UUID(spec_document_id), result.text, created_by="agent:thinker",
    idempotency_key=f"{run_id}:spec:{node_id}:{iteration}")`.
  - Return `{"document_id": spec_document_id, "prd_text": result.text}` (same shape as `pm_step`).
- Generalize the **completion branch** in `run_graph`. Replace the `if current == start_id: … else:
  <fail>` with a first-vs-later dispatch (NO start-node special-case, NO non-start fail):
  ```python
  if kind == "completion":
      n = iters_by_node.get(current, 0) + 1
      iters_by_node[current] = n
      open_invocation_step(run_id, current, n)
      if pm_document_id is None:
          # The FIRST thinker (the root): create the spec doc from the idea. Byte-identical to the
          # old PM path — same pm_step, same pm-llm / pm-prd-v1 keys.
          result = pm_step(run_id, idea, node["model"], node["prompt"])
      else:
          # A LATER thinker: read the current spec (recorded -> deterministic on resume), refine it,
          # append a new version. A thinker is now composable ANYWHERE (the pivot's last residue).
          current_spec = read_latest_prd_step(run_id)
          result = thinker_refine_step(
              run_id, idea, node["model"], node["prompt"], current, n, current_spec, pm_document_id
          )
      pm_document_id = result["document_id"]
      close_invocation_step(run_id, current, n, "done", "prd_written")
      if apply_budget_hook(run_id, node_id=current, iteration=n):
          return _finalize_over_budget(run_id, pm_document_id)
      current = next_node(edges, current, outcome=None)
  ```

  `pm_step` (key `pm-prd-v1`) and `thinker_refine_step` (key `spec:{node_id}:{n}`) are idempotent;
  `read_latest_prd_step` replays its recorded content. A second thinker on resume always re-reads
  the same recorded spec and re-appends idempotently.
- **Keep `pm_step` byte-identical.** Do not rename it, change its signature, or change its keys.
