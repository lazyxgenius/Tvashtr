### Backend contracts the FE consumes (all live on `main` — verify in Task 0, then type against them)

- **`GET /api/runs/{run_id}/graph`** → `{ run_id, team_graph_id, nodes:[…], edges:[…] }`.
  - node = `{ id, role_name, kind, model, engine, position:{x,y}, config, status, iteration }`.
    - `kind ∈ "completion" | "agent" | "gate" | "terminal"`.
    - `config` is the node's jsonb: **gate** nodes carry `{ gate_kind, title, description }` (`gate_kind ∈ "prd_approval" | "review_escalation"` for placed gates); **terminal** nodes carry `{ terminal_kind: "ship" | "stop" }`; **`null` for completion/agent**.
    - `status` = the node's latest `AgentInvocation.status`, **default `"idle"`**, `∈ "idle" | "running" | "done" | "failed" | "stopped"`. **The graph payload does NOT expose the invocation `outcome`** — so a resolved gate's approve-vs-reject distinction is **not** available from `status` (both read `"done"`); it must be read from the gate's *task* (see below).
    - `iteration` = latest invocation iteration, default `0`.
    - nodes arrive sorted by `(position.x, id)`.
  - edge = `{ id, source_node_id, target_node_id, edge_type, conditions }`. `edge_type ∈ "work" | "review" | "escalation"`. `conditions` is `null` (unconditional) or `{ when: … , …}` — `when ∈ "approved" | "rejected" | "changes_requested"`; the Reviewer→Engineer loop-back additionally carries `loop_limit` alongside `when:"changes_requested"`.
- **`GET /api/runs/{run_id}/tasks`** → `{ run_id, tasks:[…] }`, **oldest first**. task = `{ id, run_id, kind, priority, blocking, topic, title, description, status, resolution, resolution_note, created_at, resolved_at }`.
  - `priority ∈ "high_blocker" | "low_nudge"`; `status ∈ "pending" | "resolved"`; `resolution ∈ "approved" | "rejected" | "cancelled" | "acknowledged" | null`.
  - **Gate blockers** (`blocking:true`): the PRD/escalation gates have `topic = "gate:{run_id}:{node_id}"` (this is the **exact** node-link key — see the gate-node visual below). The budget breach blocker has `topic = "budget:{run_id}:{node_id}:{iter}"` (budget is policy, **not** a canvas node — it links to nothing). All blockers resolve via `/resolve`.
  - **The one non-gate task**: the budget `low_nudge` — `kind="budget_threshold"`, `priority="low_nudge"`, `blocking=false`, **`topic=null`**. Dismissed via `/acknowledge`.
- **`POST /api/runs/{run_id}/tasks/{task_id}/resolve`** `{ decision:"approve"|"reject", note?:string|null }` — **blockers only** (the workflow is signaled via `DBOS.send`); **409** if the task has no `topic`. *(Already wired in `lib/api.ts` as `resolveTask`.)*
- **`POST /api/runs/{run_id}/tasks/{task_id}/acknowledge`** (no body) — **the topic-less non-blocking nudge only**; marks it resolved directly (no `DBOS.send`); **409** if the task is `blocking` or has a `topic`, **409** if already resolved. *(NOT yet in `lib/api.ts` — you add it.)*
- **`POST /api/runs/{run_id}/cancel`** — kill switch. Note for the FE: cancel also **closes every pending task for the run** with `resolution="cancelled"` (blockers and the nudge alike). *(Already wired as `cancelRun`.)*

### B. Status model (`lib/status.ts`) — retire the hack, add gate/terminal derivations

1. **Retire the paused inference.** Change `deriveNodeStatus`'s signature to drop `predecessorDone` → **`deriveNodeStatus(backendStatus, run, workflowStatus)`**, and **delete** the `if (run?.status === "awaiting_human" && predecessorDone) return "paused"` branch. Keep `isRunTerminal`, `deriveOverall`, and the status sets exactly as they are.

2. **Add a gate-node state derivation.** A gate node's display state comes from its **matching task** (the node `status` can't distinguish approve from reject):
   ```ts
   export type GateState = "idle" | "awaiting" | "approved" | "stopped";
   export function deriveGateState(
     nodeId: string,
     runId: string,
     tasks: HumanTask[],
     run: RunRow | null,
     workflowStatus: string | null,
   ): GateState {
     const task = tasks.find((t) => t.topic === `gate:${runId}:${nodeId}`);
     if (!task) return "idle";                          // gate not reached yet
     if (task.status === "pending") {
       // normally run.status === "awaiting_human"; if the run somehow already concluded
       // (e.g. cancel races), the gate reads concluded-muted, not coral-awaiting.
       return isRunTerminal(run, workflowStatus) ? "stopped" : "awaiting";
     }
     return task.resolution === "approved" ? "approved" : "stopped"; // rejected | cancelled → stopped
   }
   ```
   (`import type { HumanTask } from "./api"` alongside `RunRow`.)

3. **Add a terminal-node state derivation** (from the node's own `status` — a terminal closes `done` once reached):
   ```ts
   export type TerminalState = "idle" | "shipped" | "stopped";
   export function deriveTerminalState(terminalKind: string, backendStatus: string): TerminalState {
     if (backendStatus !== "done") return "idle";       // not reached
     return terminalKind === "ship" ? "shipped" : "stopped";
   }
   ```

  2. **all other edges** → `type:"default"`, with `{ sourceHandle, targetHandle } = pickHandles(posById[source], posById[target])` (the geometry helper below), and a **class by category**:
     - `conditions?.when === "rejected"` → `"rf-edge--reject"` (a muted, calm branch to a stop terminal).
     - `edge_type === "escalation"` → `"rf-edge--escalation"` (a muted branch to the escalation gate — the cap-exhaustion route).

    ```ts
    function pickHandles(s: NodePosition, t: NodePosition): { sourceHandle: string; targetHandle: string } {
      const dx = t.x - s.x, dy = t.y - s.y;
      if (Math.abs(dx) >= Math.abs(dy)) {
        return dx >= 0
          ? { sourceHandle: "s-right", targetHandle: "t-left" }
          : { sourceHandle: "s-left",  targetHandle: "t-right" };
      }
      return dy >= 0
        ? { sourceHandle: "s-bottom", targetHandle: "t-top" }
        : { sourceHandle: "s-top",    targetHandle: "t-bottom" };
    }
    ```
    (Horizontal backbone edges → `s-right`→`t-left`, identical to today's look. Vertical branches → top/bottom. Leftward branches → `s-left`→`t-right`.)
