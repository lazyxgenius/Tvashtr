## Outcome (the one thing this milestone delivers)
The thinnest end-to-end **authoring** vertical of the prompt-driven node model: the user opens the
app to **one persistent, editable team** (seeded from the review-loop template), **views and edits
any agent node's `prompt` (its whole identity) and `model` in the side panel**, and presses
**"Run this team"** — which **clones the authored team into a fresh run-scoped snapshot and runs
that**, so the run is driven by the user's edits, not a hardcoded pipeline. Proven live: an edited
prompt carrying a unique sentinel drives the shipped deliverable.

User-facing behavior (this is the acceptance, in words): open app → your persistent PM → Engineer ⇄
Reviewer team is on the canvas → click an agent node → edit its prompt + model in the panel → Save
→ "Run this team" → the existing live run view takes over → the shipped artifact reflects the
edited prompt.

**Explicitly OUT of this slice (later P1.8b slices — do NOT build):** canvas topology editing
(add/remove/rewire nodes/edges), the template *library* (multiple presets + a drop UI), capability
(thinker↔worker / `kind`) editing, and **mid-run prompt re-read** (the running team uses the
immutable snapshot it launched).

## What to build (self-decompose the implementation; these are the required seams)
1. **Persistent team (one, seeded from the review-loop template).** A get-or-create of a SINGLE
   persistent `TeamGraph` from the `build_review_loop_team()` topology — re-openable across
   sessions (the same team next launch). It must NOT be created/discarded per run. (Multiple teams
   + a template library = a later slice.)
2. **Team-scoped graph read.** An endpoint returning that team's nodes + edges in the canvas's
   node/edge shape, **now including `prompt`**, with NO run-status (no `invocations` — it isn't
   running). Share the node serialization with `GET /api/runs/{run_id}/graph`, and **add `prompt`
   to that run endpoint's node dict too** (additive; the canvas already ignores unknown keys).
3. **Node update.** An endpoint to persist an edited node's **`prompt` and `model`** (ONLY those
   two fields this slice). Validate the node belongs to the persistent team; **reject editing
   gate/terminal nodes** (control primitives — no prompt/model). Simple/idempotent.
4. **Clone-on-launch (additive to POST `/api/runs`).** When the request carries the persistent
   team's `team_graph_id`, **deep-clone** its nodes + edges into a NEW run-scoped `TeamGraph`
   (fresh ids; edge source/target remapped to the cloned node ids; positions/config/prompt/model
   copied faithfully), seed `Run.team_graph_id` with the clone, and `start_workflow` exactly as
   today. The run owns an **immutable snapshot** — editing the authored team afterward must NOT
   perturb an in-flight run. The legacy `team_shape` path stays byte-for-byte unchanged (the smokes
   + A/B depend on it).
5. **FE — render + edit + run.** The canvas renders the persistent team from the team-read
   endpoint, staying `nodesConnectable=false` (NO topology edits). Clicking an **agent**
   (`completion`/`agent`) node shows, in the side panel: an **editable `prompt` textarea** + a
   **`model` field = free-text input with a small set of proven presets** as quick-pick/datalist
   suggestions (`openai/gpt-4o-mini`, `nvidia_nim/meta/llama-3.3-70b-instruct`, and the other
   in-repo slugs — a TINY STATIC list, NOT a maintained registry) + an explicit **Save**
   (dirty-aware, NO autosave) calling the node-update endpoint, then refetch. Gate/terminal nodes
   do NOT open an editable panel. A **"Run this team"** control clones+launches (POST `/api/runs`
   with the team id); the existing live run view takes over.
6. **Freeze-hook fix (ISOLATED commit).** `.claude/hooks/protect-migrations.sh`'s regex
   `^000[1-9]_.*\.py$` only covers `0001`–`0009`; bump it to freeze **`0001`–`0012`** (suggested
   `^00(0[1-9]|1[0-2])_.*\.py$`) and update the message. Keep this in its OWN commit, separate from
   the feature diff.
