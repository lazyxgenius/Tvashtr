# P0.4b — The Crash-Resume Proof (the M0 exit test)

> Second of the two P0.4 prompts. P0.4a built and verified the 2-node run (PM → Engineer → tagged ship, both nodes metered, idempotency unit-tested). **P0.4b proves it survives a deliberate `kill -9` *during the Engineer's agent run* and still ships the feature exactly once** — the milestone-M0 exit criterion — and hardens the one crash window found in review. This closes Phase 0's spine work; P0.5 (minimal UI) follows.

---

## Objective

Add `make skeleton-crash`: start a 2-node run, kill the backend process **mid agent-run**, restart it, let DBOS recover the in-flight workflow, and assert the run still completes with **exactly one** shipped (tagged) commit, **one** PRD version, and **one** agent-cost row — while proving the agent step genuinely **re-executed in the restarted process**. Also harden `idempotent_ship` so a crash *between* its commit and its tag is recoverable.

---

## Context

**Where this fits:** the final piece of P0.4 / milestone M0 ("spine proven: resumable, end-to-end"). It exercises the crash-safety the P0.4a architecture was built for — the coarse single-step agent run (Decision 1) plus the git-tag-dedup'd ship — under a real process death + DBOS recovery.

**Current state to assume (P0.4a, present and verified):**
- `backend/tvashtr/control_plane/team_run.py` — `run_team(idea)` workflow, `DBOS.workflow_id == run_id == str(Run.id)`. Steps: `load_team_config_step` → `pm_step` → `engineer_setup_step` → **`engineer_run_step`** (the one coarse agent step) → `persist_agent_cost_step` → `ship_step` → `finalize_run_step` (plus `mark_run_failed_step`). Idempotency keys are `{run_id}:pm-llm`, `{run_id}:pm-prd-v1`, `{run_id}:agent-cost`; the ship dedups on the git tag `ship-{run_id}`.
- `backend/tvashtr/control_plane/shipping.py` — pure `init_workspace_repo(ws)` and `idempotent_ship(ws, run_id)` (the one to harden).
- `backend/tvashtr/engines/run_event_sink.py` — `make_run_event_sink(run_id)` persists each `EngineEvent` to `run_events` **in its own transaction**, so events are visible in Postgres **before** `engineer_run_step` checkpoints. This is the crash-timing signal.
- `backend/tvashtr/routers.py` — `POST /api/runs` (builds the team, creates the `runs` row `status="running"`, starts `run_team` in the **background** via `DBOS.start_workflow` under `SetWorkflowID(run_id)`, returns `{run_id}`); `GET /api/runs/{run_id}` (DBOS workflow status + `runs` row + cost rows); `GET /api/spike/run-events/{run_id}` (the events). `DEFAULT_IDEA` pins `greeting.txt` containing exactly `Shipped by the Tvashtr PM->Engineer team`.
- The workspace for a run is `backend/.tvashtr_workspaces/{run_id}/` (gitignored), a git repo after `engineer_setup_step`.
- `backend/tvashtr/main.py` — FastAPI + DBOS; on launch DBOS recovers PENDING workflows for this executor (this is what resumes `run_team`).
- `scripts/crash_resume_demo.sh` + `scripts/check_crash_result.py` — **the harness pattern to mirror** (real uvicorn process 1 → wait for a checkpoint signal → `kill -9` → restart process 2 → poll to terminal → assert). Reuse its structure (`.env` sourcing, `start_uvicorn`/`wait_for_health`, `psql_c`, the pid-based assertions).
- Migrations `0001`–`0004`. Add `0005`.

**Why a real server, not `TestClient`:** P0.4a's `skeleton_run.py` drives the app in-process via `TestClient` for self-containment. **That cannot be used here** — the whole test is process death + recovery **in a fresh process**, which requires a real, separately-running `uvicorn` you can `kill -9` and restart. Use the `crash_resume_demo.sh` approach. The `POST /api/runs` endpoint works against a real server (it returns `{run_id}` immediately and runs the workflow in the background, exactly where we kill it).

## Constraints

- **Stack / conventions:** unchanged from P0.4a (DBOS 2.23.0, gateway-only litellm, adapter-only openhands, at-least-once-safe writes keyed on `DBOS.workflow_id`, single `OPENROUTER_API_KEY`, verify-don't-assume).
- **Live + opt-in:** `make skeleton-crash` runs a **real OpenHands agent**, so it must **skip cleanly** (exit 0, clear message) when `OPENROUTER_API_KEY` is unset — like `agent-smoke`/`skeleton-run`. **Both** uvicorn processes must have the key in their environment (source `.env`, as `crash_resume_demo.sh` does).
- **Exactly one deliberate crash.** Do not kill repeatedly — DBOS caps recovery attempts (`MAX_RECOVERY_ATTEMPTS_EXCEEDED`). The agent re-run must succeed on attempt 2.
- **Do NOT assert on `run_events` reflecting the winning attempt.** The sink is insert-or-ignore on `(run_id, seq)` and the adapter restarts `seq` at 0 each run, so after recovery the persisted events for colliding seqs are the **first (abandoned) attempt's**. Assert the **durable outcome**, not event-log contents. (Reporting the event count is fine.)
- **Do NOT touch / must keep green:** the P0.4a run logic (only the allowed change is hardening `idempotent_ship` + adding the attempt-log insert at the top of `engineer_run_step`), the existing migrations, and `test`/`lint`/`crash-demo`/`smoke`/`agent-smoke`/`skeleton-run`.

## Tasks (ordered)

### 1. Harden `idempotent_ship` for the commit-without-tag crash window (`control_plane/shipping.py`)
Today, if the process dies **between** `git commit` and `git tag`, the resumed `ship_step` re-runs `idempotent_ship`, finds no tag and a clean working tree (nothing staged), and **raises "nothing to ship"** — even though the ship commit already exists (untagged). Fix it so a dangling ship commit is recovered:
- Keep the fast path: tag `ship-{run_id}` exists → return `{sha, tag, created: False}`.
- When the tag is **absent** and `git add -A` leaves **nothing staged** (`git diff --cached --quiet` exits 0): **before raising**, check whether `HEAD`'s commit message is exactly `Ship: {run_id}` (e.g. `git -C <ws> log -1 --format=%s`). If so, the commit was made but not tagged (crash window) → **create the tag on HEAD** and return `{sha: HEAD, tag, created: False}`. Only raise "nothing to ship" if HEAD is **not** the ship commit (genuinely nothing was produced).
- Behaviour is otherwise unchanged (commit + tag on the normal path).
- **Unit test** (`backend/tests/test_shipping.py`): init a repo, write the file, then **manually** `git add -A` + `git commit -m "Ship: run-x"` **without tagging** (simulating the crash window), then call `idempotent_ship(ws, "run-x")` → assert it does **not** raise, creates the `ship-run-x` tag pointing at the existing HEAD, returns `created=False` with `sha == HEAD`. The existing ship tests must still pass.

### 2. Attempt log — proof the agent step re-executed (migration `0005` + ORM)
Add a minimal table (a tiny stand-in for the data model's `AgentInvocation`, kept deliberately small) to make re-execution **observable**, mirroring how `crash-demo` uses recorded pids:
- ORM `EngineerRunAttempt` (`models.py`) + migration `0005_engineer_run_attempts`: `id` (BigInteger Identity pk), `run_id` (Text, indexed), `pid` (Integer), `created_at` (timestamptz, server_default now).
- In `engineer_run_step` (`team_run.py`), **at the very top of the step, before the agent runs**, insert one row recording `os.getpid()`. **This insert is intentionally NOT idempotent** — one row per execution, so a crash-then-resume yields **two** rows with **different** pids (the whole point).
- `alembic check` clean after `0005`; `downgrade -1` + re-`upgrade head` round-trip.

### 3. The crash harness — `scripts/skeleton_crash_demo.sh` (mirror `crash_resume_demo.sh`)
- **Skip cleanly** if `OPENROUTER_API_KEY` is unset (print a clear message, exit 0).
- Source `.env` (so **both** processes get the key); `docker compose up -d` + wait for Postgres + `alembic upgrade head`.
- Start uvicorn **process 1** (real server, `--log-level warning`), `wait_for_health`; record `OLD_PID`.
- `POST /api/runs` (empty body — uses the pinned idea) → `RUN_ID`.
- **Wait for the agent to be mid-run:** poll `GET /api/spike/run-events/{RUN_ID}` (or the DB) until **the first event appears** → the agent has started inside `engineer_run_step`, before it checkpoints. (Optionally wait for the first `action` to be certain it's doing work — first event is acceptable.)
- **Show the state at crash and sanity-check it:** the run has **not** shipped yet (no `ship-{RUN_ID}` tag in the workspace, `runs.status` not `completed`), and there is exactly **one** `engineer_run_attempts` row for `RUN_ID` with `pid == OLD_PID`.
- `kill -9 $OLD_PID`; wait for it to die.
- Start uvicorn **process 2**, `wait_for_health`; record `NEW_PID`. DBOS recovers the PENDING `run_team` → `engineer_run_step` re-runs (a fresh agent run) → `persist_agent_cost` → `ship` → `finalize`.
- Poll `GET /api/runs/{RUN_ID}` until `runs.status == completed` (and/or workflow `SUCCESS`), with a generous timeout (the agent re-run is a full run — e.g. 360s). Bail clearly on `ERROR`/`CANCELLED`/`MAX_RECOVERY_ATTEMPTS_EXCEEDED`.
- Run the checker; print a final `SKELETON CRASH-RESUME PASSED` banner on success. Exit non-zero on any failure/timeout.

### 4. The assertions — `scripts/check_skeleton_crash.py` (run with the backend venv)
Takes `RUN_ID OLD_PID NEW_PID BASE_URL`. Assert (exit non-zero with a message on any failure):
- **Recovered & completed:** DBOS workflow status `SUCCESS` **and** `runs.status == completed`.
- **Shipped once:** `runs.ship_tag == ship-{RUN_ID}` and `runs.ship_commit_sha` set; in the workspace repo, exactly **one** tag matches `ship-{RUN_ID}` (`git tag --list "ship-{RUN_ID}"` → 1 line) **and** exactly **one** commit has message `Ship: {RUN_ID}` (`git log --all --grep "Ship: {RUN_ID}" --oneline` → 1 line).
- **Feature present:** `git show ship-{RUN_ID}:greeting.txt` equals `Shipped by the Tvashtr PM->Engineer team`.
- **One PRD version:** the run's `pm_document_id` has exactly **one** `DocumentVersion` (`version_no == 1`) — the atomic doc helper held across the crash.
- **Metering idempotent:** exactly **one** `CostRecord` for `{RUN_ID}:agent-cost` and **one** for `{RUN_ID}:pm-llm`.
- **Re-execution proof:** `engineer_run_attempts` for `RUN_ID` has **≥ 2** rows; the **earliest** pid `== OLD_PID` (pre-crash) and the **latest** pid `== NEW_PID` (restarted) and `OLD_PID != NEW_PID` — i.e. the agent step genuinely re-ran in the new process, yet (per the checks above) the feature shipped **exactly once**. (This is the keystone: re-execution + exactly-once outcome.)
- (Optional/report-only: print the `run_events` count for `RUN_ID`; do **not** assert it reflects the winning attempt.)

## Explicit verifications (confirm by observation — do not assume)
1. **DBOS recovers `run_team` in the restarted process.** Show the polled status transitions from process 2 (PENDING/recovering → SUCCESS). This is the crux of the test.
2. **The agent step re-executed.** The `engineer_run_attempts` table shows two rows with distinct pids (`OLD_PID` then `NEW_PID`).
3. **Exactly-once outcome despite re-execution.** One `ship-{RUN_ID}` tag/commit, one PRD version, one `{RUN_ID}:agent-cost` row — even though the agent ran twice.
4. **One crash is enough** and the agent succeeds on attempt 2 (no `MAX_RECOVERY_ATTEMPTS_EXCEEDED`).

## Acceptance criteria
- **`make skeleton-crash` (with key):** starts a run, kills process 1 **mid agent-run** (proven: killed right after the first `run_event`, with no ship tag and one attempt row `pid==OLD_PID` at crash), restarts as process 2, DBOS recovers `run_team`, and the checker passes **all** of §4 — most importantly **≥2 engineer attempts with distinct pids (OLD_PID earliest, NEW_PID latest) yet exactly one `ship-{RUN_ID}` tag/commit, one PRD version, one agent-cost row, and the committed file matches**. Exits non-zero on any failure/timeout. Skips cleanly (exit 0) without a key.
- **Ship hardening:** the new commit-without-tag unit test passes (recovers by re-tagging HEAD, no raise); all existing `test_shipping` tests still pass.
- **Regressions green:** `make test`, `make lint`, `make crash-demo`, `make smoke`, `make agent-smoke`, `make skeleton-run`. `alembic check` clean after `0005`; `downgrade -1`/`upgrade head` round-trip.
