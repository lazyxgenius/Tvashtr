# P0.5b — Inspect the Work (node-select side panel: PRD + versions, run-event feed) + the M0 walkthrough that closes Phase 0

> Second and final P0.5 prompt — and the **last step of Phase 0**. P0.5a delivered the living canvas (the 2-node team, live per-node status, polled). P0.5b makes the team's *output* inspectable: click a node to open a side panel — the **PM** shows its **PRD + version history**, the **Engineer** shows its **run-event feed** (the agent's action/observation stream). Then a short **M0 exit-criteria walkthrough** formally closes Phase 0. After this, Phase 1 (Supervisor scoping + a real default team) begins.
>
> **Scope note: this is frontend-only + one docs file.** Every endpoint the panel needs already exists. **No backend code, no new endpoint, no migration.**

---

## Objective

1. **Selection → side panel.** Clicking a canvas node opens a DS-styled right-hand panel for that role; clicking empty canvas or a close button closes it. The canvas stays usable (the panel must not permanently obscure the selected node).
2. **PM panel = the PRD.** Render the PM's document (latest version) as clean, readable text, plus a **version history** list; selecting a version shows that version's content. (Today there is only `v1`; build it as a list so Phase-1 edits appear.)
3. **Engineer panel = the run-event feed.** Render the agent's events as a concise, readable log (a summary per event — not raw JSON), polled ~2s and appended live while the run is active.
4. **M0 walkthrough.** A short `docs/` walkthrough mapping each Phase-0 exit criterion to its proof (the `make` targets + the now-inspectable UI), run once live through the UI, formally closing Phase 0.

Polling, not WebSockets. Plain render, not TipTap. The canvas itself (P0.5a) is unchanged except for adding selection.

## Context

**Where this fits:** the capstone of Phase 0. P0.4 proved the resumable spine; P0.5a made it *visible*; P0.5b makes its artifacts *inspectable* and then documents Phase-0 closure. The side panel is also the seed of the Phase-1 pattern (select a node → read/edit its documents).

**Backend endpoints the panel consumes (all present — do NOT modify them):**
- `GET /api/runs/{run_id}` → `{run_id, workflow_status, run: {…, pm_document_id, ship_tag, ship_commit_sha, cost_total_usd, status, …}, costs:[…]}`. **`run.pm_document_id`** is the id of the PM's PRD document (null until the PM step finishes). Already polled by `App.tsx` (P0.5a).
- `GET /api/documents/{document_id}` → `{id, title, doc_type, created_at, updated_at, versions:[{id, version_no, content, created_by, created_at}]}`. `400` on a non-UUID id, `404` if not found. Versions are ordered ascending by `version_no`.
- `GET /api/spike/run-events/{run_id}` → `{run_id, events:[{seq, kind, payload, created_at}]}`, ordered by `seq`. **This is the Engineer's feed.** (It's a P0.3 "spike"-named route; keep using it as-is. Promoting it to `/api/runs/{id}/events` is a trivial future cleanup, **out of scope here** — do not rename it, the crash harness/scripts may reference it.)

**The `run_events` payload shapes (verified in `engines/openhands_adapter.py::_payload_of`) — drive the feed's concise summary from these:**
- `kind="action"` → `{"tool_name": str|null, "thought": str, "action": str}`
- `kind="observation"` → `{"tool_name": str|null, "observation": str}`
- `kind="message"` → `{"source": str, "text": str}`
- `kind="error"` → `{"error": str}`

All string fields are already server-truncated (≤1000–2000 chars) but can still be multi-line/verbose — so render a **short single-line summary** per event (with the fuller text available on hover/expand), never a raw JSON dump. Two caveats to honor in the UI copy: (a) only the **Engineer** (agent) node emits `run_events` — the PM is a direct completion with no feed; (b) after a crash-recovery the feed is **not** "winning-attempt-only" (events for colliding `(run_id, seq)` are the first/abandoned attempt's, by the insert-or-ignore design) — fine for a feed, but add a quiet one-line note so it isn't mistaken for a clean winning-attempt log.

- `frontend/src/lib/api.ts` — typed client (`startRun`, `getGraph`, `getRunStatus`, `getHealth`, plus `RunRow`/`GraphData`/etc.). **Extend this** (don't fork it) with the document + events calls.

## Constraints

- **Frontend-only + one docs file.** No backend changes, **no new endpoint, no migration**. If you find yourself editing anything under `backend/tvashtr/`, stop — the data you need is already served.
- **Extend, don't fork.** Add to `lib/api.ts`, `lib/status.ts` (or a small new `lib/events.ts`), and the existing CSS — keep one client, one status module, one token system.
- **Plain render, not TipTap.** The PRD is rendered as readable text (`white-space: pre-wrap`, body type, a comfortable reading measure) — **no markdown library, no rich editor** (TipTap is Phase 1). If the PM's text contains markdown syntax, showing it literally is acceptable.
- **Polling, not WebSockets.** The feed polls `GET /api/spike/run-events/{run_id}` ~2s **only while the Engineer panel is open and the run is non-terminal** (plus one fetch on open and one final fetch when the run reaches terminal); no polling when the panel is closed or the run is done. Clean up intervals on unmount/close. (WebSocket remains the named Phase-1 upgrade.)
- **Canvas stays read-only and intact.** The only change to the canvas is **adding selection** (report a clicked node's role up; deselect on pane click). Do not add authoring, do not change `nodesConnectable={false}`, do not regress the P0.5a look/motion.
- **Motion is calm.** The panel opens/closes with a bounded fade/slide (≤320ms, `--ease-standard`, no bounce); the feed appends without flashing; no infinite animations. A node-status change still uses the P0.5a bounded one-shot pulse.
- **Don't touch / must stay green:** all backend (`team_run.py`, `shipping.py`, `teams.py`, `routers.py`, `models.py`), migrations, and the make targets `test`/`lint`/`crash-demo`/`smoke`/`agent-smoke`/`skeleton-run`/`skeleton-crash`. `npm run build` (strict typecheck + build) must pass.
- **Read the skills:** your built-in `frontend-design` skill + `Design System/SKILL.md`.

## Tasks (ordered)

### 1. `lib/api.ts` + `lib/events.ts` — the new data calls and the event summarizer
- Add to `lib/api.ts` (additive): types `DocumentVersion` (`{id, version_no, content, created_by, created_at}`), `DocumentDetail` (`{id, title, doc_type, created_at, updated_at, versions: DocumentVersion[]}`), `RunEvent` (`{seq, kind, payload: Record<string, unknown>, created_at}`), `RunEventsResponse` (`{run_id, events: RunEvent[]}`); and calls `getDocument(id)` → `GET /api/documents/{id}` and `getRunEvents(runId)` → `GET /api/spike/run-events/{runId}` (reuse the existing `getJSON` helper).
- Add `lib/events.ts` with a pure `summarizeEvent(kind, payload)` → `{ tone: "neutral" | "danger"; label: string; lead: string; detail: string }`, mapping the verified payload shapes to a concise row:
  - `action` → label `"action"`, lead = `tool_name ?? ""`, detail = first non-empty line of `thought` (fallback `action`).
  - `observation` → label `"observation"`, lead = `tool_name ?? ""`, detail = first non-empty line of `observation`.
  - `message` → label `"message"`, lead = `source`, detail = first non-empty line of `text`.
  - `error` → label `"error"`, tone `"danger"`, detail = `error`.
  Trim/normalize whitespace; cap `detail` (e.g. ~140 chars) and expose the fuller text for a tooltip/expand. Defensive against missing keys (never throw).

### 2. Selection wiring — `TeamCanvas.tsx` + `App.tsx`
- `TeamCanvas`: accept `onSelectNode?: (role: string | null) => void`. Call `onSelectNode(node.data.role_name)` from `onNodeClick`, and `onSelectNode(null)` from `onPaneClick`. (React Flow's own `.selected` ring still works — this just lifts the role up.) Do not otherwise change canvas behavior.
- `App`: add `selectedRole` state. Pass `onSelectNode={setSelectedRole}` to `TeamCanvas`. **Reset `selectedRole` to `null` when a new run starts** (in `handleStart`). Render the new `<SidePanel>` (task 3) as a sibling of `<TeamCanvas>` inside `<main>`, passing `selectedRole`, `runId`, `run`, `workflowStatus`, and `onClose={() => setSelectedRole(null)}`.

### 3. The side panel container — `panel/SidePanel.tsx` (+ styles)
- A DS-styled right-hand panel that is present when `selectedRole !== null`. **Do not permanently obscure the selected node:** prefer a **push/split** layout — the panel takes a fixed width (~380–420px) on the right and the canvas (`flex-1`) shrinks beside it; trigger a gentle `fitView` when the panel opens/closes so the 2 nodes stay visible. (An overlay + auto-refit is acceptable if cleaner, but the node you clicked must remain reachable.)
- Panel chrome: a header with the role title (sentence case — "Product manager" / "Engineer") + a quiet close button (ghost icon); a hairline left border; paper surface; a soft shadow is acceptable here (DS allows shadows for floating panels). Calm open/close (≤320ms, no bounce).
- Body switches on role: `selectedRole === "pm"` → `<PrdView …/>` (task 4); `selectedRole === "engineer"` → `<EventFeed …/>` (task 5).
- Preserve the canvas height chain (the P0.5a `#root` flex column / `main` flex-1 / canvas `h-full`); the panel must scroll internally, not blow out the layout.

### 4. PM panel — `panel/PrdView.tsx`
- Props: the run's `pm_document_id` (from `run`). When it's **null** (PM still drafting / no run): a calm placeholder — e.g. *"The product manager is drafting the spec…"* (or, before any run, *"No spec yet."*). When present: fetch `getDocument(pm_document_id)` **once on open**, and **refetch if `pm_document_id` changes** (e.g. the PM finishes while the panel is open) — effect keyed on `[pm_document_id]`. Handle fetch error gracefully (*"Couldn't load the spec."*).
- Render: the document title + a compact **version list** (each: `v{version_no}` · `created_by` · short timestamp), the latest selected by default; clicking a version shows its `content`. Render `content` as **plain readable text** — `white-space: pre-wrap`, Inter, a comfortable measure (~`--measure-read`), in a scrollable region. No markdown parsing.

### 5. Engineer panel — `panel/EventFeed.tsx`
- Props: `runId`, `run`, `workflowStatus`. Fetch `getRunEvents(runId)` on open; then **poll ~2s while the run is non-terminal** (use `isRunTerminal`), doing one **final** fetch when it becomes terminal; **stop** polling when terminal or on unmount/close. Append/replace by `seq` (idempotent — seqs are stable). No polling when closed.
- Render each event as a concise row via `summarizeEvent`: a small **kind badge** (DS Badge vocabulary; `error` → danger tint), the `lead` (tool/source) in mono, and the `detail` one-liner (truncated, `title`/expand for the full text), plus a short timestamp. **Chronological (seq ascending), newest at the bottom; auto-scroll to the newest row** as events arrive (but don't fight a user who has scrolled up — only auto-scroll if already near the bottom).
- States: no events yet (PM still running / engineer not started) → *"No activity yet — the engineer hasn't started."*; fetch error → graceful message. Include a **quiet one-line note** that, after a crash-recovery, the feed shows the first attempt's events for repeated steps (not winning-attempt-only) — so it's not misread.

### 6. The M0 exit-criteria walkthrough — `docs/M0-walkthrough.md` (+ run it live)
- Write `docs/M0-walkthrough.md`: a short, skimmable doc that (a) states Phase-0's exit criteria and milestone M0, (b) maps **each** criterion to its **proof**, and (c) declares Phase 0 closed. Map at least:
  - *idea → 2-agent run* → `make skeleton-run` (or the UI "Start the run"): PM + Engineer as one DBOS workflow.
  - *one versioned PRD doc* → the `documents`/`document_versions` rows, now **viewable in the UI** (select the PM node → PRD + versions).
  - *trivial feature committed* → the `ship-{run_id}` tagged commit of `greeting.txt`, shown in the run banner (ship sha) and the workspace repo.
  - *resumable across a deliberate crash* → `make skeleton-crash`: `kill -9` mid agent-run, DBOS recovers, ships **exactly once** (distinct attempt pids).
  - *the spine is now observable* → the canvas (live per-node status) + PRD view + run-event feed.
- Include a brief **"walk it yourself"** UI section: `make backend` + `make frontend` → open `localhost:5173` → **Start the run** → watch nodes idle→running→done → click **PM** (read the PRD + versions) → click **Engineer** (watch the feed) → banner shows **Shipped** + cost + ship sha.
- **Run this live yourself once** (with `OPENROUTER_API_KEY`): start a run through the running app, exercise both panels, and report what you observed (PRD content rendered; feed rows for the agent's actions/observations; banner shipped). If you can't run it, say so explicitly and leave the live run to the operator.
