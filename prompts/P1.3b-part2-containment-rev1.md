## Why this revision (what the live run found)
The operator ran `make containment-smoke` against real Docker. **All three privileged escape writes were DENIED by the container's own filesystem permissions** — before the Docker boundary was even in play:
- `echo … > /escape_abs.txt` → `cannot create /escape_abs.txt: Permission denied` (exit 2)
- `echo … > ../escape_traversal.txt` (→ `/escape_traversal.txt`) → `Permission denied` (exit 2)
- `mkdir -p '<REPO_ROOT>'` → `cannot create directory '/Users': Permission denied` (exit 1)

The agent-server runs the shell as a **non-root user that cannot write the container's `/`** (or create top-level dirs). So every write failed, every in-container `test -f` returned ABSENT, and the script's non-vacuous guard **correctly** refused to declare containment proven (`in_container_present=False` → exit 1). **This was the guard working as designed** — it caught a vacuous proof. Everything else passed: container up on an ephemeral port, the real pull shipped exactly `['keep.txt']`, host clean, pull-target clean, container reaped (no orphan).

**The insight:** there are TWO containment layers, and the original vectors only probed for the *absence* of the second:
1. **Least-privilege (inside the container):** the agent can't even write privileged out-of-`/workspace` paths (`/`, `/Users`, …) — denied outright. (An OpenHands-image property we hadn't credited.)
2. **The Docker boundary (no bind-mount, `--rm`) — what P1.3 actually built:** never exercised, because no write ever landed *outside* `/workspace` to then be shown unable to reach the host.

To prove the **boundary** specifically, the agent must write somewhere it *can* (outside `/workspace`) and we show even that is trapped in the ephemeral container. `/tmp` is provably writable in this image — the server's own logs show it using `/tmp/openhands-agent-server-8`. `/tmp` and `/var/tmp` are standard sticky world-writable dirs (mode 1777), both outside `/workspace`, and neither can be `/workspace`.

## The fix (Option A — operator-approved): keep both layers, make the assertions outcome-aware
Keep the three privileged vectors (they evidence **least-privilege** when denied) and **add two writable vectors** (`/tmp/escape_tmp.txt`, `/var/tmp/escape_vartmp.txt`) that are expected to **land** in the container and then be shown **trapped** (absent on host, excluded from the pull) — evidencing the **Docker boundary**. Make every assertion **outcome-aware** so we never re-assume the container's permission model: each vector is "contained" whether it was *denied outright* OR *landed-and-trapped*, and we report which. The unified claim becomes:

> **Every out-of-`/workspace` write is contained — privileged ones denied outright, writable ones trapped in the ephemeral container — and the host stays clean.**

**2. Replace the now-wrong PASS logic.** The old "**all** escapes must be PRESENT in-container" is wrong (it made denied-privileged-writes a FAIL). Replace with **outcome-aware** classification:
- For each vector: issue the write (keep printing its `exit_code`/`stderr` — the writability probe), then `test -f <abs path>` → `landed ∈ {True, False}`.

  - `selectivity = no escape basename in pulled` (nothing escaped via the pull).
  - `host_clean = not new_leaks` (nothing reached the host fs).
  - `pull_target_clean = no escape basename under the pull-target`.
  - `keep_ok = keep.txt captured ∧ host content == LEGIT_CONTENT`.
  - **`PASS = boundary_exercised ∧ keep_ok ∧ selectivity ∧ host_clean ∧ pull_target_clean`.**
  - (Note: because PASS already requires `selectivity ∧ host_clean`, EVERY landed vector is provably contained — none reached the pull or the host. `boundary_exercised` guarantees ≥1 vector landed, so the boundary was genuinely tested, not assumed.)
- **Report the honest two-layer breakdown:**
  - per vector: the write's `exit_code` + a classification — `DENIED in-container (least-privilege)` if `not landed`, else `LANDED → contained (boundary)`.
  - `least_privilege`: the list of DENIED vectors (expect the 3 privileged).
  - `boundary`: the list of LANDED-and-contained vectors (expect the 2 writable).
  - if `boundary_exercised` is False, print an explicit, actionable line: *"no out-of-/workspace write landed — could not exercise the Docker boundary; add another writable target"* (do not silently pass).
  - keep the existing selectivity / host-clean / pull-target lines.
- Update the docstring + summary to the two-layer framing (least-privilege + boundary), replacing the old "all three PRESENT" narrative.

Robustness note (outcome-aware, not re-assuming permissions):** if a *privileged* vector unexpectedly LANDS (a future image makes `/` writable), it simply classifies as LANDED and must be contained like any other — the proof still holds via the boundary layer; report it under `boundary` with a note.
