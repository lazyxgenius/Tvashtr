### 1.1 The node/edge model today (`team_run.py::load_graph_step`)

`load_graph_step(run_id)` builds the picklable graph the walk uses. Each node dict is currently:

```python

    {"id": str(n.id), "role_name": n.role_name, "kind": n.kind,
     "model": n.model, "config": n.config}
    for n in nodes
]
```

Each edge dict: `{"source", "target", "edge_type", "conditions"}`. `start_node_id` = the unique
node with no incoming edge (the root; the PM in both teams) — **already topology-derived, not
role-hardcoded. Leave that logic intact.**

`AgentNode` (in `models.py`) today has `role_name`, `kind`, `model`, `engine`, `config` — and
**no `prompt` column**. `kind ∈ {"completion", "agent", "gate", "terminal"}`:
`completion` = a direct LLM completion (the "thinker" tier — the PM today); `agent` = a
sandboxed OpenHands run (the "worker" tier — Engineer + Reviewer today); `gate`/`terminal` are
control primitives. **This `kind` already encodes the thinker/worker capability — you do NOT add
a capability column. Only `prompt` is new.**

### 1.3 The routing primitives (`team_run.py`)

```python
def next_node(edges, source_id, outcome):
    out_edges = [e for e in edges if e["source"] == source_id and e["edge_type"] != "escalation"]
    if outcome is not None:
        for edge in out_edges:
            conditions = edge["conditions"]
            if conditions is not None and conditions.get("when") == outcome:
                return edge["target"]
    for edge in out_edges:
        if edge["conditions"] is None:          # <-- the fallthrough (unconditional) edge
            return edge["target"]
    return None
```

`escalation_target(edges, source_id)` → the `edge_type=="escalation"` edge's target (the cap
route). `loop_limit_for(edges, node_id, default)` → the `loop_limit` on the loop-back edge whose
`target == node_id` (matched by the `loop_limit` key, **"when"-agnostic** — important below), else
`default` (`Settings.max_review_iterations`, 3).

### 1.4 The review_loop edges today (`teams.py::build_review_loop_team`)

- `pm → prd_gate` : `conditions=None`, `edge_type="review"` (or default)
- `prd_gate → engineer` : `{"when": "approved"}`
- `prd_gate → stop` : `{"when": "rejected"}`
- `engineer → reviewer` : `conditions=None`, `edge_type="review"`
- **`reviewer → engineer` : `{"when": "changes_requested", "loop_limit": N}`, `edge_type="review"`**  ← the loop-back
- `reviewer → ship` : `{"when": "approved"}`, `edge_type="review"`
- `engineer → escalation_gate` : `conditions=None`, `edge_type="escalation"`
- `escalation_gate → ship` : `{"when": "approved"}`
- `escalation_gate → stop` : `{"when": "rejected"}`

(The 2-node team: `pm → prd_gate → engineer → ship`, with `engineer → ship` unconditional.)

### 1.5 The verdict harvest today (`team_run.py::_harvest_verdict`)

`reviewer_agent_run_step` runs the agent, then `_harvest_verdict(workspace)` reads + removes
`{workspace}/REVIEW_VERDICT.json`, parses defensively, and returns
`{"outcome": "approved"|"changes_requested", "reasons": str|None}`. **Crucial current behavior:**
a missing / malformed / unrecognized verdict ⇒ `"changes_requested"` (safe-default toward more
review, never a silent approve). The executor routes on that outcome via `next_node`.

`run_graph` closes the Reviewer invocation with the harvested outcome + `outcome_detail=reasons`;
closes the Engineer invocation with the literal `"built"`.

### 1.6 The forced-revisions harness (keeps the live smokes LLM-free)

`reviewer_agent_run_step` reads `TVASHTR_FORCE_REVISIONS=N` **FIRST**, before any adapter
resolution: it returns `changes_requested` while `iteration <= N` else `approved`, with **zero**
usage and **no** adapter run. This is what keeps `loop-run`/`loop-crash`/`skeleton-*` and the
offline tests LLM-free and `team_run` openhands-free at import. **This property MUST be
preserved.** (The Engineer has no forced short-circuit — it always runs the real adapter, which
is why `loop-run`/`loop-crash` are "live" smokes needing `TVASHTR_AGENT_MODEL`.)

### 1.7 The cost keys today

- Engineer: `persist_agent_cost_step` → idempotency key `{run_id}:agent-cost:{iteration}`.
- Reviewer: `persist_reviewer_cost_step` → key `{run_id}:reviewer-agent-cost:{iteration}` (a
  deliberately distinct namespace; only written when usage is non-zero).

The checkers (`loop_run.py`, `check_loop_crash.py`, `check_skeleton_crash.py`) count
`CostRecord.idempotency_key LIKE '{run_id}:agent-cost:%'` (a **prefix** match) and assert exact
counts (skeleton: 1; loop-run forced: 2; loop-crash FORCE_REVISIONS=2: 3). **Because it is a
prefix match, appending `:{node_id}` to the key keeps these assertions valid**, and the forced
Reviewer writes zero cost rows so it never adds to the `agent-cost:%` count.

### 1.8 The EngineerRunAttempt row & the crash demos

`engineer_run_step` writes one `EngineerRunAttempt(run_id, pid=os.getpid())` per execution (NOT
idempotent — one row per run, the re-execution proof). `loop_crash_demo.sh` polls until the
`engineer_run_attempts` count reaches 2 to know "Engineer iteration 2 is in flight", then
`kill -9`s. `check_loop_crash.py` / `check_skeleton_crash.py` assert the attempt pids span
OLD→NEW. **EngineerRunAttempt has `run_id` + `pid` only — no `node_id`, no `iteration`.**
→ **Implication:** in the merged generic agent step, the attempt row must be written **only when
the real adapter actually runs** (after the forced short-circuit). In forced mode the Reviewer
short-circuits and writes no attempt row, so the attempt count stays Engineer-only and the crash
demo's trigger is unchanged.

### D4 — `node_emits_outcome` (the role-agnostic discriminator)

New pure, importable, unit-tested helper:

```python
def node_emits_outcome(edges, node_id):
    """True iff some non-escalation out-edge of node_id has a conditional `when` —
    i.e. the user wired this node to branch the walk on a routing label (a 'reviewer-style'
    node). A node with only an unconditional out-edge (an 'engineer-style' worker) returns
    False. This replaces the `config.agent_kind == 'reviewer'` dispatch with a fact about the
    authored topology."""
    return any(
        e["source"] == node_id
        and e["edge_type"] != "escalation"
        and e["conditions"] is not None
        and "when" in e["conditions"]
        for e in edges
    )
```

With the current builders: Reviewer → True (`{when:approved}` out-edge); Engineer → False (only
`→reviewer` unconditional + `→escalation_gate`); 2-node Engineer → False.
