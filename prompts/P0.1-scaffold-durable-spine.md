The sleep duration must be overridable (param or env) so tests can shrink it.
6. **API handles.** `POST /api/spike/hello-durable` → starts the workflow in the background (DBOS background start/enqueue), returns `{workflow_id}`. `GET /api/spike/hello-durable/{workflow_id}` → returns the DBOS workflow status plus the recorded `spike_hello_events` rows for that workflow.
7. **Crash-resume demo.** `scripts/crash_resume_demo.sh`, invoked by `make crash-demo`: (a) `docker compose up -d` Postgres + wait healthy; (b) run migrations; (c) start uvicorn in the background, record its PID; (d) POST to start the workflow; (e) wait until the step-1 event row exists; (f) `kill -9` uvicorn; (g) print the events table ("state at crash"); (h) restart uvicorn; (i) poll the GET endpoint until status is SUCCESS (timeout 60s); (j) print final events and **assert**: exactly one row per step, and step 1's pid ≠ steps 2–3's pid (proof that step 1 was not re-executed and steps 2–3 ran in the new process). Exit non-zero on any failed assertion or timeout.
