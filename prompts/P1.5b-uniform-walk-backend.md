## Objective

Turn `run_team` from "fixed pre/post phases wrapping one generic sub-walk" into **one uniform node/edge walk with no special-cased phases**. Introduce two new node kinds — **`gate`** (a human-approval checkpoint the walk pauses at and routes from) and **`terminal`** (the walk's endpoint: ship-and-finalize, or stop) — so the inlined PRD-approval gate, the review-escalation, and the ship/finalize steps all become **graph nodes the walk visits**, and the PM also folds into the walk. **Budget stays a cross-cutting policy (NOT a node):** a between-spend-steps hook raising a `budget_approval` blocker, plus an 80%-of-cap **`low_nudge`** producer. Both hardcoded builders place the new nodes; the graph endpoint exposes each node's `config`; a small **acknowledge** endpoint resolves a topic-less nudge.

The existing live targets (`make skeleton-run` / `skeleton-crash` / `loop-run` / `loop-crash`) must keep passing **unchanged in outcome** — they ARE the regression/durability proof that the rewritten walk stays crash-durable. No new crash proof in this prompt.

**Out of scope (later prompts):** the frontend; canvas authoring (placing/moving gates is Phase 2); per-node/per-project budgets; the reviewer per-round verdict view; docker-mode loop seeding; parallel branches.

## Task 4 — the uniform walk `run_graph` (generalize `run_review_loop`)
Rename/replace `run_review_loop` with **`run_graph(run_id, graph, idea)`** — a workflow-body helper that walks from `graph["start_node_id"]` following edges until a `terminal` node ends it (or an error / over_budget / escalation-reject short-circuits). It owns workflow-local `current`, a per-node iteration map (`iters_by_node`), a lazily-created `workspace` (None until the first agent node), `prd_text`, and `reviewer_feedback`. It returns the dict `run_team` hands back to the caller (Task 6). Dispatch per node `kind`:

- **`completion`** — increment this node's iteration `n`; `open_invocation_step(run_id, current, n)`. If `current == graph["start_node_id"]` → it's the **PM/author**: `pm = pm_step(run_id, idea, node["model"])`; set `prd_text = pm["prd_text"]`; `close_invocation_step(..., "done", "prd_written")`; `outcome = None`. Else it's the **Reviewer**: `verdict = reviewer_decide_step(run_id, node["model"], n, prd_text, workspace)`; `close_invocation_step(..., "done", verdict["outcome"])`; `reviewer_feedback = verdict["reasons"]`; `outcome = verdict["outcome"]`. Then run the **budget hook** (Task 5) — if it says stop, finalize `over_budget` + return; else `current = next_node(edges, current, outcome)`. (Structural PM-vs-Reviewer dispatch by start-node identity — NOT a `role_name` check; a richer `completion_kind` discriminator is the P1.8 generalization, leave a one-line comment saying so.)
- **`agent`** — increment `n`; `limit = loop_limit_for(edges, current, get_settings().max_review_iterations)`. **Cap-guard (enforced termination, same semantics as 5a's `if n > max_iters`):** if `n > limit`, do NOT run the agent — set `current = escalation_target(edges, current)` and `continue` the walk (it lands on the review-escalation gate node, which pauses + routes). Otherwise: lazily create the workspace if `workspace is None` (`workspace = engineer_setup_step(run_id)`); `open_invocation_step(run_id, current, n)`; `vkey = mint_vkey_step(run_id)`; `engineer = engineer_run_step(run_id, prd_text, workspace, node["model"], vkey, n, reviewer_feedback)`; `delete_vkey_step(run_id, vkey)`. Handle the result EXACTLY as 5a's loop does: `over_budget` → (best-effort `persist_agent_cost_step` if non-zero) + `close_invocation_step(..., "stopped", "over_budget")` + return `{"outcome": "over_budget"}`; status `!= "completed"` → `close_invocation_step(..., "failed", None)` + return `{"outcome": "failed", "error": engineer.get("error")}`; else `persist_agent_cost_step(run_id, node["model"], engineer, n)` + `close_invocation_step(..., "done", "built")` + run the **budget hook** (stop → finalize `over_budget` + return) + `current = next_node(edges, current, outcome=None)`.
- **`gate`** — `open_invocation_step(run_id, current, 1)`; `cfg = node["config"] or {}`; `gate = wait_at_gate(run_id, topic=f"gate:{run_id}:{current}", kind=cfg.get("gate_kind", "gate_approval"), priority="high_blocker", blocking=True, title=cfg["title"], description=cfg["description"])`; `close_invocation_step(run_id, current, 1, "done", gate["resolution"])`; `current = next_node(edges, current, gate["resolution"])`. (Node-id-scoped topic → concurrent gates never collide; the `(run_id, topic)` open-idempotency holds. A gate has no iteration loop — iteration is always 1.)
- **`terminal`** — `open_invocation_step(run_id, current, 1)`; `cfg = node["config"] or {}`; if `cfg.get("terminal_kind") == "ship"`: `ship = ship_step(run_id, workspace)` → `final = finalize_run_step(run_id, "completed")` → `close_invocation_step(..., "done", "shipped")` → return the completed dict (run_id/status="completed"/document_id/ship_sha/ship_tag/cost_total). Else (stop): `final = finalize_run_step(run_id, "rejected")` → `close_invocation_step(..., "done", "stopped")` → return the rejected dict (status="rejected"). A terminal **ends the walk** (set `current = None` / return).

**Determinism note to honor:** `prd_text`/`reviewer_feedback`/`workspace` all come from recorded step outputs (`pm_step`/`reviewer_decide_step`/`engineer_setup_step`), and every routing decision comes from a recorded output (gate resolution, verdict, engineer status, budget verdict) — so the walk replays identically. Defensive: an unknown `kind` ends the walk safely (return an `approved`-equivalent / a clear failure — your call, but don't loop forever).
