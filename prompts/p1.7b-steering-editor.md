# P1.7b — Live PRD steering: TipTap editor + steering-state UI + live J3 E2E

> The FE half of P1.7. P1.7a (backend, merged @ `4f5cf04`) already made the in-flight PRD a live
> steering surface: a recorded `read_latest_prd_step` re-sources the LATEST `DocumentVersion` of the
> run's `pm_document_id` at every agent-node entry, and `POST /api/documents/{id}/versions` appends a
> human edit as a new version. **This slice makes that surface human-usable through the UI and proves
> J3 end-to-end through the real editor.** It is FRONTEND-ONLY — the backend save endpoint, the read
> step, and the service helpers are all done. Do not touch the backend.

---

## 1. Outcome (the one thing this milestone delivers)

In the PM side-panel, while a run is in-flight, the **latest** PRD version renders in a **TipTap
(ProseMirror) markdown editor**. A human edits it and clicks **Save** → the full edited markdown is
POSTed to the existing `POST /api/documents/{id}/versions` (a new `created_by:"human"` version) → the
panel refetches and shows the new version. The running agents re-source that edit on their next node
entry (J3 — already wired). Editing is **gated on the run being in-flight**; a terminal run shows the
PRD **read-only** (the current plain-text render). Proven by a **live Playwright E2E** that edits the
PRD at the PRD gate through the real UI and asserts the shipped deliverable reflects the human's edit.

## 2. Context — current state on disk (READ these before starting)

**The save endpoint (DONE, P1.7a) — `backend/tvashtr/routers.py`:**
- `POST /api/documents/{document_id}/versions`, body `AddDocumentVersionRequest { content: str }` — the
  **full** new content (NOT a patch). Server sets `created_by="human"` and a fresh idempotency key per
  POST → **every POST is a new version**. 400 on a malformed id, 404 if the doc doesn't exist.
- Response is a **partial** shape: `{ document_id, version_no, content, created_at }` — note **no
  version `id`, no `created_by`**. So after a save, **refetch** the document via `GET
  /api/documents/{id}` (returns the full version list, ascending by `version_no`) to refresh the panel.
- `GET /api/documents/{id}` returns `{ id, title, doc_type, created_at, updated_at, versions: [{ id,
  version_no, content, created_by, created_at }] }`.

**The read path (DONE, P1.7a) — `backend/tvashtr/control_plane/team_run.py`:**
- `read_latest_prd_step(run_id)` reads `Run.pm_document_id` → `get_latest_version` → `.content`,
  called at every agent-node entry (the Engineer + Reviewer, every iteration). The Engineer
  instruction is **purely PRD-driven** ("Read the following PRD and create exactly the file it
  specifies, with exactly the specified contents") — **no original idea is embedded** — so a human
  PRD edit deterministically wins (this is why the E2E sentinel is reliable).
- **The editor's save target = `run.pm_document_id` = the exact document `PrdView` already receives.**

**The FE surface to change:**
- `frontend/src/panel/PrdView.tsx` — currently renders `selected.content` as **plain text** in a
  `tv-prd__content` div, with a version-button list; fetches the doc once on `documentId` change
  ("No markdown lib" — it explicitly anticipates "a Phase-1 edit creates a new doc"). Props today:
  `{ documentId: string | null, emptyHint: string }`.
- `frontend/src/panel/SidePanel.tsx` — PM role → `<PrdView documentId={run?.pm_document_id ?? null}
  emptyHint={…} />`. It already receives `run: RunRow | null` and `workflowStatus: string | null`.
- `frontend/src/lib/api.ts` — has `getDocument(id)`; `DocumentVersion`/`DocumentDetail` types. **No
  version-POST client yet** — add one. Mirror the existing `fetch` helpers (e.g. `acknowledgeTask`).
- `frontend/src/lib/status.ts` — owns the terminal/failed sets (e.g. `WORKFLOW_FAILED`); `abCompare.ts`
  reuses them via `isSideTerminal`. **Reuse these for the editable-gating helper — do not redefine
  terminal sets.**
- `frontend/src/App.tsx` — polls `getRunStatus` + `getGraph` (~2s) and threads `run` + `workflowStatus`
  into `SidePanel`. `PrdView` fetches the doc only on `documentId` change, so polling will NOT clobber
  an in-progress edit (`pm_document_id` is stable once the PM writes v1). **App.tsx needs no behavioral
  change** — at most thread an `editable` value into `SidePanel`→`PrdView`, but `SidePanel` already has
  `run`+`workflowStatus`, so the gating can be derived inside `SidePanel`/`PrdView` with no App.tsx edit.
- CSS: token-only, additive, house style (cream/coral/Newsreader). New editor styles go in
  `frontend/src/panel.css` (or a small new stylesheet `@import`ed from `index.css`, per the §14.3
  `abcompare.css` precedent). No ad-hoc hex; use the design-system tokens.

**Stack — `frontend/package.json`:** React `^19`, Vite `^7`, vitest `^3.2`, Tailwind `^4`, TS `^5.6`.
Scripts: `dev` (vite), `build` (`tsc --noEmit && vite build`), `test` (`vitest run`). No ESLint/
Prettier, no Playwright (both are added here only as needed — see Tasks).

**Live-target pattern — `Makefile` + `scripts/`:** `make X` → `cd backend && <ENV> uv run python

- **The single-run canvas + the A/B tree render byte-identical.** This is purely additive to the PM
  panel. `App.tsx`'s run/AB state, the `mode` toggle, and the poll loop keep their current behavior; the
  single-run tree must not regress.
- **Editor changes confined to:** `panel/PrdView.tsx`, the `PrdView` call site in `panel/SidePanel.tsx`,
  `lib/api.ts` (additive: the version-POST client), `lib/status.ts` (additive: only if the editable
  helper lives there) or a new pure helper module, new CSS (token-only, additive), `package.json` (add
  deps), new tests, and the new E2E + its `make` target/script.
- **NO new `eslint-disable` comments.** The new code passes `tsc --noEmit` strict **cleanly**.
  (ESLint/Prettier + RTL are a separate, later FE-infra step — out of scope here.)
- **The TipTap markdown round-trip must be FAITHFUL** — a no-op load-then-save must NOT mutate the spec
  (the round-trip-stability test below is the guard; if `tiptap-markdown` defaults are lossy on a
  construct the PM emits, constrain the editor schema/serializer until stable).
- Editing applies only to the **latest** version; older versions stay read-only (browse history).
- **No autosave** — Save is explicit and dirty-aware (enabled only when the content changed). Every POST
  is a new version; the steering model is deliberate.
- **No fake lock UI** — the soft-lock is a registered §15 deferral (only the PM writes the PRD, so a
  human edit can't collide with an agent write). Surface **steering state**, not a lock.

## 4. Tasks (suggested decomposition — self-decompose/reorder as needed)

1. **Deps.** Add TipTap (`@tiptap/react`, `@tiptap/starter-kit`, `@tiptap/pm`) + a markdown round-trip
   extension (e.g. `tiptap-markdown`, or `prosemirror-markdown` directly) — pin to versions compatible
   with **React 19** and verify the build is clean. Add `@playwright/test` (dev) + install the chromium
   browser for the E2E only.
2. **`lib/api.ts` — the version-POST client.** `addDocumentVersion(documentId: string, content: string)
   : Promise<{ document_id: string; version_no: number; content: string; created_at: string }>` — POST
   `/api/documents/${documentId}/versions`, body `{ content }`, mirroring the existing `fetch` helpers
   (throw on `!res.ok`). Keep `getDocument` for the post-save refetch.
3. **The editable helper (pure, unit-tested).** A pure function — reuse `status.ts`'s terminal/failed
   sets — `isPrdEditable(runStatus: string | null, workflowStatus: string | null): boolean`, true iff
   the run is **non-terminal** (in-flight). Unit-test it (terminal statuses → false; running/awaiting →
   true; null → false).
4. **`PrdView.tsx` — the editor.** When `editable`:
   - Render the **latest** version's markdown in a TipTap markdown editor (load markdown → editor doc;
     on save, serialize editor doc → markdown).
   - A **dirty-aware Save** button (enabled only when content changed). On Save → `addDocumentVersion`
     → `getDocument` refetch → select the new latest version → clear the dirty flag.
   - Selecting an older version shows it **read-only** (the current plain-text render); only the latest
     is editable.
   When NOT `editable`: the current read-only plain-text render, unchanged. Thread `editable` from
   `SidePanel` (derive it there from `run.status` + `workflowStatus` via the helper; no App.tsx edit
   required).
5. **Steering-state affordance (Q2).** When editable: copy framing the edit as live steering — e.g.
   *"This is the live spec — saving creates a new version the agents read on their next round."* After a
   save: a confirmation — e.g. *"Saved v{N} — the agents read it on their next round."* (always "next
   read/round", never "now"). Mark the latest version as the current/live one in the list (the list
   already shows `created_by`, so a `human` edit is visibly attributable). No lock badge.
6. **Round-trip-stability vitest test.** A representative PRD fixture matching the PM's PRD shape — a
   `#` heading, a `-` bullet list, AND a fenced code block containing a file path + the exact deliverable
   line — fed through the editor's markdown parse → serialize → assert **byte-stable** (idempotent
   no-op). Make it **non-vacuous**: assert the fenced code block and the exact deliverable line survive
   verbatim. If lossy, constrain the schema/serializer config until it passes.
7. **Live J3 E2E — `make steering-e2e`.** Playwright against the **running** stack (backend
   `TVASHTR_AGENT_SANDBOX=local`, **NO** `TVASHTR_AUTO_APPROVE_GATES`, real NIM agent from `.env`; the
   Vite dev server up). Orchestrate start/teardown like `scripts/hitl_demo.sh` + a Vite server (a
   `scripts/steering_e2e.sh` wrapper + a Playwright spec under `frontend/e2e/` is a fine layout). Flow:
   1. Start a `review_loop` run (the UI "Start" control).
   2. Wait until it **pauses at the PRD gate** (`awaiting_human`) — the gate blocks indefinitely, so
      there is no timing race.
   3. Open the PM panel; **assert the TipTap editor renders** the PM's PRD.
   4. **Clear the editor and type a known minimal PRD** that specifies a file `greeting.txt` at the repo
      root containing exactly a **SENTINEL** line (a unique string distinct from `DEFAULT_IDEA`'s line,
      e.g. `Steered by a human mid-run via Tvashtr <nonce>`). **Save** → assert a new version (its
      `created_by` is `human`) appears.
   5. **Approve the PRD gate** (the Tasks-for-Human drawer).
   6. Wait until the run **ships** (`completed`).
   7. **Assert the shipped `greeting.txt` contains the SENTINEL line, NOT the original `DEFAULT_IDEA`
      line** (read it from the ship tag / shipped workspace, as `scripts/check_*` do). This proves a
      human **rewrote the spec mid-run through the real UI and the agent followed it** — full J3.
