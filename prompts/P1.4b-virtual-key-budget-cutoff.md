# P1.4b — Per-run virtual key + the mid-loop spend cutoff (the agent's loop is cut off *inside* a run)

## Objective
Give the LiteLLM proxy **teeth**: mint a **per-run virtual key** with a `max_budget`, hand it to the OpenHands agent in place of 4a's master key, and let the **proxy error mid-call** when the agent's spend hits that budget — stopping a runaway agent *inside* a single run. The adapter **classifies** that budget error and the run finalizes **`over_budget`** (reusing P1.2's terminal). This is **enforcement only** — full metering-collapse stays deferred. Deliver a live `make proxy-budget-demo` that makes the mid-loop cutoff visible (the felt signal of this stretch).

## Context (where it fits + current state on disk)
Phase 1, **P1.4b** — the second half of the agent-internal spend chokepoint. 4a put the agent's traffic *through* the proxy (opt-in) but added no enforcement; 4b adds the per-key budget that cuts a runaway agent off **mid-loop** (the hard cutoff P1.2's between-steps gate can't do). `main` is at the P1.4a fast-forward merge + the Tvashtr-11→12 handover doc commit; P1.4a is CLOSED.

**The design is LOCKED (Tvashtr-12, §17 — read that entry). Build exactly this; do not re-litigate:**
- **Mint = a durable Control-Plane `@DBOS.step`** inside `run_team`, right before the engineer runs (NOT at the HTTP endpoint, NOT a `Run` column — **no migration**). The key rides the step's checkpointed output into the engineer step and into teardown. (Rationale: keeps the secret off the app's API surface, keeps the whole key lifecycle durable/resumable like every other run side-effect, and is the seam that extends to per-invocation keys in P1.5.)
- **Budget on the key = the *remaining* budget** = `cap − running_cost(run_id)` computed **at mint time** (after the PM has run, so `running_cost` already includes the PM's spend). Two **uncapped-key** guards: if the run is **already `budget_overridden`** (human approved a P1.2 breach = "continue to completion") → mint with **no** `max_budget`; if the run has **no cap** (`budget_cap_usd is None`) → mint with **no** `max_budget`. One per-run cap, enforced from two angles (proxy = mid-step cutoff; P1.2 gate = between-steps), no double-count.
- **Breach → `over_budget`:** extend `AgentRunResult.status` to `Literal["completed","failed","over_budget"]`; a shared predicate classifies the proxy's mid-call budget error (the **exact** error type/HTTP status/body is the open item from 4a — **capture it live in Task 0 and pin the predicate to it**); `engineer_run_step` surfaces the status; `run_team` routes `over_budget` → `finalize_run_step("over_budget")` (no ship). P1.2's between-steps gate stays (defense-in-depth; the two never both fire — the proxy cutoff returns before the pre-ship gate).
- **Partial spend:** the proxy's **server-side budget (in the `litellm` DB) is the authoritative cutoff** — enforcement is exact regardless of our ledger. Additionally record whatever partial agent spend is cleanly readable from the cut-off conversation, **best-effort**, via the existing idempotent `persist_agent_cost_step`. **Do NOT** build exact spend reconciliation — that's the staged §15 metering-collapse, not 4b.
- **Teardown = both:** a **TTL** (`duration`) on the key at mint is the reliable floor (no teardown step can be skipped by a crash; orphan keys self-clean); **plus** a **best-effort delete** step right after the agent runs (invalidate the live credential immediately; TTL backstops a skipped/failed delete so it adds no correctness dependency).
- **Demo (`make proxy-budget-demo`):** proxy ON + **docker** mode + a **tiny run cap** so `remaining` is small → the agent's loop blows through the key budget → proxy errors mid-call → terminal **`over_budget`**, asserting **no `budget_approval` HumanTask was ever created** (proving the *mid-loop proxy cutoff* stopped it, not the between-steps gate).
