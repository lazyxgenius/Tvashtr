## 3. Architect rulings — final

- **R1 Time limits and states.** Every model call has a time limit (120 s, `agent_request_timeout_s`).
  A step is **Quiet** after 90 s with no new event and no command running, **Stalled** after 5 min.
  A command that is running is never Quiet; it shows its own running time and latest output and is
  bounded by its tool's own timeout. A step Stalled for 20 min is ended as Failed with
  `failure_code="stalled"` ("The Engineer stopped responding: no update for 20 minutes"), its sandbox
  released, and the run offered for Resume. All four numbers are env-dialable
  (`TVASHTR_QUIET_AFTER_S`, `TVASHTR_STALLED_AFTER_S`, `TVASHTR_STALL_FAIL_AFTER_S`, existing timeout).
- **R2 Retries and the backup model.** A 429, 5xx, connection error or timeout is retried with
  backoff, 3 tries. When the tries are used up (or on a hard failure), the step switches ONCE to its
  backup model: the node's `config.fallback_model`, else `teams.account_fallback_model` for its
  capability — only if the owner holds a key for it and it differs from the primary. Each retry and the
  switch is a run event the Activity feed shows, and the switch also records a `RunWarning`. Where the
  retry happens inside the sandbox and the host can't see it, the Quiet state covers it — do not patch
  the in-container agent-server.
- **R3 Team versions.** The team as you edit it is a working copy, kept exactly as today (the drawer's
  Save and "All changes saved" don't change). A version is an explicit checkpoint: the header shows
  `v7 · saved 2m ago`, or `v7 · 2 changes since v7` with a **Save as v8** button (this replaces the
  boards' "2 unsaved changes" copy — update the boards). Starting a run with changes since the last
  version saves them as a new version first, so every run has a version. Layout-only changes (moving a
  node, Tidy, groups) never make a version. Restore makes a NEW version equal to the old one; nothing is
  deleted; a run in flight keeps its version. Existing teams get v1 = their current state.
- **R4 My agents.** Using a saved agent applies at once with Undo in a toast — no confirm dialog. The
  node keeps its memory and routes; the drawer shows "Based on <name> v<n>" with Detach.
- **R5 Compare.** Both versions run at the same time on separate copies of the repo. Compare runs never
  ship (no PR, no branch push) and approve gates automatically by default (a switch turns that off).
  They queue when the caps are full.
- **R6 Checks when saving** run right after the save, never blocking it. Their results sit next to the
  version in History; if a version does worse, Restore is one click.
- **R7 AI checks** run on Tvashtr's own key with a small model, never the owner's key: server settings
  `TVASHTR_CHECKS_MODEL` and `TVASHTR_CHECKS_API_KEY`, limit 200 per account per month ("186 of 200 left
  this month"). With no key configured, AI checks show "Not available yet" and are skipped, not failed.
  Production has no such secret: build it gated and list "add the two Fly secrets" as an operator
  action. A check counts as trusted once it agrees with the person's labels on at least 8 of 10.
- **R8 Resume** makes a new run linked to the old one, on the old run's team snapshot (not the current
  team), same repo/base settings. Everything before the chosen step is carried (shown "Carried over",
  never re-run, never re-billed); the chosen step and everything after it run again; round numbers
  continue (Engineer round 2). The workspace is rebuilt from a durable checkpoint, never from the old
  sandbox. Resume points are agent steps of a run that ended failed, stopped, stalled or cancelled. The
  existing "Retry" stays exactly as it is.
- **R9 Start from a run** carries, by choice: the final spec (it becomes the starting spec), your
  decisions, the confirmed memories, a short summary from each agent. Never the agents' full
  conversations. "Start from": the run's PR branch (when not merged) or `main`. It uses the team as it
  is now (its current version).
- **R10 Notifications:** ask once (the bell in the run bar); three per-account choices (needs you /
  stalls or fails / finishes) stored as new keys in `preferences.py`'s whitelist; Desktop uses native
  notifications, the website the browser Notifications API when allowed; each notification opens its
  run.
- **R11 Hidden checks** of a task set never reach any agent: not in any prompt, file, memory or event
  the agents can read.
- **R12 Caps:** agent-test replays count toward the per-owner concurrency cap only (each capped at 10
  minutes); compare runs count fully, like any run.
- **R13 Failure path:** an edge "If it fails or times out" makes the walk follow it when the agent
  fails (error, R1 stall ceiling, or its own time limit) instead of failing the run. One failure path
  per agent; loop limits still apply. Each agent can set its own time limit (default from R1).
- **R14 Tidy and groups** change positions/labels only — no effect on how work flows, no version.
- **R15 Transport:** keep polling (2 s). WebSockets stay deferred.
- **R16 Desktop releases:** every ship that changes `frontend/` or `desktop/` bumps `desktop/package.json`
  one minor version (0.15.0, 0.16.0, …) and is tagged. A backend-only ship has no Desktop release.

## 6. Ship Protocol — after every milestone

1. **Gates** — all must pass; echo each command and its decisive line:
   - `make test` on `tvashtr_gate`: 0 failed, count ≥ the floor.
   - `cd frontend && npx vitest run`, `npx tsc --noEmit`, `npm run build`; `cd desktop && npm test`.
   - `docker build -t tvashtr-ship .`
   - eslint `--max-warnings 0` + prettier on changed frontend files; ruff check + format-check on
     changed backend files (the old baseline in untouched files is out of scope).
   - **Parity:** shoot every board of the milestone (and every board you added) on web and Desktop,
     with scenario fixtures in `scripts/design-parity/scenarios/` mirroring the boards' data; record in
     `docs/superpowers/parity/<milestone>.txt`: the new elements at 0 size/type drift; existing elements
     and chrome carry `# waiver: app governs (brief 2.2/2.3)`; real "not found in app" items get built.
   - **Kept-elements check** (2.2): every touched existing screen's inventory is a superset.
   - **Independent review** by a helper that didn't build the milestone: correctness, owner scope (one
     test per new route), auth, and this brief's rules. Fix what it finds (bugs test-first). Echo its
     findings and what you did about each.
   - Every e2e spec that touches the area, plus `revamp-shell`, plus the milestone's new spec, against
     the real stack (clear stale runs + PENDING DBOS workflows first).
   - `make demo-proof` C1–C12 with a real PR (`make seed` first; up to 3 attempts for provider flakes).
2. Append the milestone's section to `docs/superpowers/HANDOVER-2026-10-02-m1-m11.md` (Changed ·
   Verified · Assumed · Not done) and commit it on the branch.
3. If `frontend/` or `desktop/` changed: bump `desktop/package.json` (+ lock) one minor (R16) and commit.
4. `git fetch origin`; if `origin/main` moved, merge it into the branch (no rebase) and redo step 1.
5. From the main checkout: `git checkout main && git pull --ff-only origin main &&
   git merge --ff-only <branch> && git push origin main`, and push the branch. Never force. If the
   fast-forward fails, go back to step 4.
6. **Ask for the ship approval.** Echo a SHIP REQUEST: the milestone, the `main` sha to deploy, the
   gates' result lines, the new migrations (or "none"), whether `team_run.py`/an engine adapter/the
   gateway changed, the Desktop version to tag (or "none"), and this approval line filled in for the
   operator to paste back:
   `APPROVED M<n> ship: take Neon snapshot snap-m<NN>-<YYYYMMDD-HHMM> of production (project billowing-mud-37479513), fly deploy main <sha> to app tvashtr (runs alembic upgrade head: <migrations or "no migration">), roll back to the previous image if the smoke fails, then push tag desktop-v<version>.`
   Leave out the snapshot clause when there is no migration and no executor/adapter/gateway change, and
   the tag clause when there is no Desktop release. Then work on the next milestone (§0 rule 10) until
   the approval arrives. Act only on an approval that names this milestone and this sha; if `main` has
   moved, post a fresh request. A reply "skip M<n> deploy" means: record it and deploy it with the next
   approved ship (deploys are cumulative).
   On approval: (a) take the Neon snapshot when the line names one, with `neon branches create
   --project-id billowing-mud-37479513 --name <name> --parent production --no-compute --no-secrets -o
   json` (the `neon` binary above), and echo the branch list; (b) confirm no run is in flight on prod
   (no `tv-run-*` Fly app; the logs quiet for 2 minutes). If one is, wait up to 30 minutes, then ask
   the operator again instead of deploying.
7. `fly deploy`. Confirm the release command (`alembic upgrade head`) ran. Smoke: `/health`
   `{"status":"ok","db":"ok"}` and `/healthz`; headless Playwright loads the landing and sign-in pages
   with 0 page errors; the JS asset name in the live `index.html` equals your local build's;
   `make deploy-smoke` 0 failed; the milestone's new routes answer 401 without a session (never 500);
   0 5xx and 0 tracebacks in `fly logs` for 5 minutes. Run `make demo-proof-prod` only if its saved
   session is still valid; if stale, say so and move on. **If the smoke fails:** roll back as the
   approval allows (`fly releases --image`, then `fly deploy --image <previous>`), confirm health, write
   NEEDS_HUMAN and stop the session — never ship onto a broken production.
8. Desktop release (only if step 3 bumped and the approval names the tag): `git tag desktop-v<version> <main sha> && git push origin
   desktop-v<version>`; wait for the "Desktop Mac Release" workflow (poll the public API or the redirect
   of `…/releases/latest/download/Tvashtr-mac.dmg`, up to 30 minutes); download the DMG, mount it
   read-only (`hdiutil attach -nobrowse -readonly`), confirm the app's version and that its bundled JS
   asset equals the live one; detach. If the workflow isn't done in 30 minutes, record it as an
   operator check and continue (don't stop the session).
9. Update the handover file and the `STATE.md` ledger; echo exactly one line:
   `MILESTONE <n> SHIPPED: main=<sha> fly=v<N> desktop=<tag|none>`.

  GitHub sign-ins; anything needing a password, key or account you don't have.
- **Invariants — show each with a command at every ship:** no frozen migration changed
  (`git diff <previous main> <new main> -- backend/alembic` lists only new files); the `EngineAdapter`
  signature and `build_two_node_team` unchanged (`git diff` of those definitions empty); no assertion
  weakened (`git diff <previous main> <new main> -- backend/tests frontend/src frontend/e2e | grep -E
  '^-\s*(assert |expect\()'` — every hit explained or replaced by a stricter one); nothing from
  `design/`, `HANDOVER.md`, `PROJECTPLAN.md`, `prompts/`, `STATE.md` committed; Fly secrets untouched
  (only `fly secrets list` ever ran); production data untouched apart from migrations.
