## Objective
Add a **Docker-sandboxed execution path** for the agent — the OpenHands **agent server in a container**, driven via `openhands.workspace.DockerWorkspace` behind the **existing `EngineAdapter` contract** — so the demonstrated write-escape is contained by a real boundary instead of a prompt band-aid. Land it as a **selectable mode (default stays `local` in P1.3a)**; the agent's output crosses back to the host via **pull-at-end** (no bind-mount); orphaned containers are **reaped**. The contract, the event seam, the usage-telemetry path, and the host-side idempotent ship all hold across the move.

## Context
The §13 top safety item: the unsandboxed write-escape is **DEMONSTRATED** (P0.4b — the agent wrote `greeting.txt` outside its workspace on an absolute `/greeting.txt` path; the current fix is a prompt-level band-aid, not containment). P1.3 is the fix. Slotted after the kill switch (P1.1) + caps (P1.2) so containment-verification runs are already killable + cost-capped. The `EngineAdapter` **contract is the durable asset** (`engines/base.py`); only the OpenHands adapter's *guts* move from in-process `LocalConversation` to a containerized `RemoteConversation`. The agent run stays the **one coarse `@DBOS.step`** (`engineer_run_step`) — Decision 1 (restart + idempotent ship) is preserved; P1.3a builds the lifecycle + reaping that P1.3b then proves under a real crash.

## Verified facts you are building on (confirmed against installed 1.28.1 + OpenHands docs — re-confirm against the disk per Task 0)
- **`openhands.workspace.DockerWorkspace`** is a **context manager** that pulls/starts the agent-server container, waits for ready, and tears down on `__exit__`. `Conversation(agent=..., workspace=docker_ws, callbacks=[...])` then **automatically returns a `RemoteConversation`** (assert this).
- **Event seam is preserved:** `callbacks=[on_event]` still fire — events stream over WebSocket from the server as the same `ActionEvent`/`ObservationBaseEvent`/`MessageEvent`/`AgentErrorEvent` types the current `_kind_of`/`_payload_of` map. (One stale SDK docstring says callbacks are "not yet streamed" — the code + the official example contradict it. **The live check must confirm `on_event` actually fires;** treat it as the #1 thing to verify live.)
- **Usage seam is preserved, identical accessor:** `conversation.conversation_stats.get_combined_metrics()` → `accumulated_token_usage` / `accumulated_cost`. `_read_usage()` works unchanged over the remote path (the official example uses this exact call on a `RemoteConversation`).
- **Image:** `ghcr.io/openhands/agent-server:latest-python`, `platform=detect_platform()` → `linux/arm64` on this Mac (operator confirmed the arm64 manifest exists). The image is heavy (VSCode/VNC baked in) — set `extra_ports=False` (we don't need them).
- **Workspace API for pull-at-end:** `RemoteWorkspace` (which `DockerWorkspace` extends) exposes `file_download(src, dest)`, `git_changes(path)`, `git_diff(path)`, `execute_command(cmd)`. **No host bind-mount.**
- **The LLM key travels in the agent config**, not the container env: the adapter builds `LLM(model=eng_model, api_key=OPENROUTER_API_KEY, ...)`; the SDK serializes it (with secrets exposed) to the server, which makes the calls. The container needs egress to OpenRouter (default). The live check must confirm the agent authenticates.
- **No Python `docker` lib is installed** — do reaping by shelling out to the `docker` **CLI** via `subprocess` (mirror `shipping.py`'s subprocess-to-`git` pattern).

## Resolved design (DQ1–DQ4 + architect calls — implement exactly)

**DQ1 — ship bridge = PULL-AT-END (no bind-mount).** The agent works in the container's own workspace dir. After `conversation.run()`: enumerate the agent's changed files and `file_download(...)` them (bytes over HTTP) into the host `.tvashtr_workspaces/<run_id>`; then `idempotent_ship(host_workspace, run_id)` runs **host-side exactly as today** (the `ship-{run_id}` tag dedup is unchanged and stays host-side — it carries Decision 1). `files_changed` comes from the enumerated/downloaded set. **Rationale (do not revisit):** avoids the macOS Docker-Desktop bind-mount UID/permission/perf footgun and is the strictest boundary. Pin the enumeration mechanism against the installed source — the container workspace starts empty, so "list everything under the container working dir and download it" is the simplest correct approach; `git_changes` against the init commit is the alternative. **Two-way-door:** pick whichever the installed API makes clean; log it.

**DQ2 — crash-resume = Decision-1 restart + idempotent ship + ORPHAN REAPING.** A `kill -9` kills the Python client, not the container, so a crashed run leaves an orphaned agent-server container (its `__exit__` teardown skipped) holding its port. Build reaping (P1.3b proves it under a real crash):
- **Boot-time sweep:** at backend startup, force-remove **all** Tvashtr agent-server containers (single-operator v1: any such container at boot is orphaned). This is what clears a crash orphan before a resumed `engineer_run_step` starts a fresh container.
- **Reap-before-start:** at the top of the agent run (docker mode), force-remove any prior agent-server container for this run before starting a fresh one.
- **Targeting:** pin against how `DockerWorkspace` names/labels its container (read its source). If it accepts a custom name or label, use a deterministic per-run identifier (e.g. `tvashtr-run-{run_id}`) and reap by that; if not, reap by the agent-server image (`ancestor=`) — acceptable single-operator. **If safe per-run reaping is impossible without an architectural choice, ESCALATE.** Log the targeting choice in the ledger.
- Keep the agent run as the **one coarse `engineer_run_step`** (start container → run → pull → teardown all inside it); on re-run it re-produces the output and the host-side `ship-{run_id}` dedups → exactly once. Do **not** attempt agent-native resume / reconnect-to-surviving-container — that is the **named §15 upgrade, deliberately deferred** (do not build it; it's already registered).

**DQ3 — containment acceptance = reframe the band-aid (proof is P1.3b).** In `engineer_run_step`'s instruction, the "if the PRD shows a leading `/` or `./`, ignore it and write relative" text did two jobs: (1) prevent host escape — now redundant (the container is the boundary), and (2) ensure the deliverable lands in the workspace so it ships — **still needed** (the cheap PM model emits absolute paths; ship-dependent regressions need the file in the workspace). **Reframe, don't remove:** keep a relative-path instruction worded as plain happy-path correctness ("write the deliverable into your working directory using a relative path so it can be shipped"), with the **security justification dropped** (the container, not the prompt, is now the boundary). Build NO forced-escape proof here — that is P1.3b.

**DQ4 / architect call — selectable mode; DEFAULT STAYS `local` in P1.3a.** Land the containerized path behind the `EngineAdapter` contract, selected by a new `Settings` flag:
- `Settings.agent_sandbox_mode: Literal["local", "docker"] = "local"` (env-overridable, e.g. `TVASHTR_AGENT_SANDBOX`). **Default `local`** — do **not** flip it (the flip to `docker` is P1.3b, after containment + crash-resume are proven over the container). This is a deliberate "prove it, then default it" staging; the local path stays the default so the proven machinery is undisturbed this step.
- **Structure (two-way door — pick one, log it):** either a second adapter (e.g. `OpenHandsDockerAdapter`, `name="openhands-docker"`) registered alongside the existing one and resolved by the setting, **or** a mode branch inside the existing `OpenHandsAdapter` choosing `DockerWorkspace` vs the local dir. Either way: the **`EngineAdapter` contract is unchanged**, the returned `AgentRunResult` shape is identical (status / events / files_changed / usage), and **only the containerized adapter module imports `openhands.workspace`, lazily** (boundary discipline — see hard rails).
