## Objective

Upgrade the review-loop's **Reviewer from a `completion` node to a full `agent` node**
(behind the existing, unchanged `EngineAdapter`; it runs in the sandbox like the
Engineer). The agent-Reviewer **runs the deliverable's test suite** and judges the build
against the **original idea + the PRD**, then emits its verdict as a **structured sidecar
artifact** — `REVIEW_VERDICT.json` — which the Control Plane reads, parses defensively,
and removes. This is the §15-registered "reviewer `completion`→`agent`" upgrade and
realizes the vision's ship gate (J1 step 8: ship on *passing tests*, reviewed against the
idea).

Non-negotiable invariants:
- The **forced-revisions harness stays intact** so `loop-run` / `loop-crash` / `skeleton-*`
  stay **LLM-free and green** (the forced path must short-circuit **before** any agent run).
- The **Engineer path is behavior-identical** (its instruction, its `…:agent-cost:{n}` key,
  its crash-resume are all untouched).
- **No migration** (the `agent_nodes.config` jsonb exists from `0009`). **No Makefile
  change. No frontend change.**

The *real* agent-Reviewer (no harness) is exercised live in the next prompt, on a real
multi-file feature. This prompt is **fully offline-verifiable** (new offline tests + the
existing regression suite), plus the operator re-running the existing `loop-run`/`loop-crash`
to confirm the forced path still works end-to-end.

## Constraints

**Stack/conventions (follow exactly):**
- Steps are `@DBOS.step()`; routing/orchestration lives in the **workflow body** (`run_graph`,
  which is NOT a step — it issues `wait_at_gate`/`recv` and calls steps). The forced-revisions
  and the verdict harvest must be read/done **inside a recorded step** so a crash-resume
  replays the same verdict (the loop's control flow depends on it) — mirror how
  `reviewer_decide_step` reads `TVASHTR_FORCE_REVISIONS` inside the step today.
- Idempotency keys are `{run_id}:…` strings. The Reviewer's cost key MUST be **distinct**
  from the Engineer's (see Tasks) so the Engineer's `{run_id}:agent-cost:{n}` key stays
  byte-for-byte (the `skeleton-crash`/`loop` checkers match `…:agent-cost:%`).

  `resolve_adapter`, which is already imported at the top of `team_run.py`). `team_run.py`

- Defensive parsing: a Reviewer whose job is to test must **fail toward more review**. A
  missing/malformed/unrecognized verdict ⇒ **`changes_requested`** (never silently

- New pure helpers (verdict harvest, gitignore writer, review-instruction builder) must be

- `build_two_node_team` in `teams.py` (its Engineer stays config-less → the dispatch treats

- The **Engineer path** in `run_graph`: its instruction (incl. the iteration-1 byte-for-byte

### Task 4 — `team_run.py`: the agent-Reviewer step + the verdict contract
Add the new step + helpers (stdlib-only helpers are importable + unit-tested):

**4a. The review-instruction builder** (pure):
```python
def _build_review_instruction(prd_text: str, idea: str) -> str:
    ...
```
The instruction must tell the Reviewer agent, in order:
1. Inspect the files in your current working directory (the engineer's build).
2. Run the test suite with **exactly** `python -B -m unittest` (the `-B` is required — do not
   write bytecode).
3. Decide the verdict: `"approved"` **only if** the tests pass **and** the deliverable
   fulfills the **original idea** and the **PRD**; otherwise `"changes_requested"` (any test
   fails, a required behavior/file from the idea or PRD is missing, or it otherwise falls
   short).
4. Write a file named **exactly** `REVIEW_VERDICT.json` in the current working directory (the
   bare filename), containing **exactly** this JSON and nothing else:
   `{"verdict": "approved" | "changes_requested", "reasons": "<1-3 short, specific, actionable sentences>"}`.

   Strict rules to include verbatim in spirit: "You are REVIEWING, not editing. Do NOT
   modify, create, or delete ANY file except `REVIEW_VERDICT.json`." and "Base `approved` on
   the tests actually passing and the spec actually being met — do not approve on assumption."

   End the instruction with `--- ORIGINAL IDEA ---\n{idea}\n\n--- PRD ---\n{prd_text}`.

**4b. The verdict harvest** (pure; read-parse-**remove**):
```python
_REVIEW_MAX_REASONS = 2000

def _harvest_verdict(workspace: str) -> dict:
    """Read {workspace}/REVIEW_VERDICT.json, parse defensively into
    {"outcome": "approved"|"changes_requested", "reasons": str|None}, and REMOVE the file so
    it never ships and never seeds the next iteration. Safe-default: missing/malformed/
    unrecognized -> changes_requested."""
```
Behavior:
- Path = `Path(workspace) / "REVIEW_VERDICT.json"`.
- If it doesn't exist → return the safe default `{"outcome":"changes_requested","reasons":
  "(no REVIEW_VERDICT.json produced — defaulting to changes_requested)"}` (nothing to remove).
- Else read it; try `json.loads`:
  - On a valid object, read `verdict` = `str(raw.get("verdict","")).strip().lower().replace(" ","_")`:
    - `"approved"` → `{"outcome":"approved","reasons":None}`.
    - `"changes_requested"` → `{"outcome":"changes_requested","reasons": <raw.get("reasons") str, capped to _REVIEW_MAX_REASONS, or a "(no reasons given)" fallback>}`.
    - anything else → safe default.
  - On `json` failure → a **lightweight text fallback**: if the raw file text contains
    `"approved"` and not `"changes"` (case-insensitive) → approved; else → the safe default
    `changes_requested` (carry a short snippet of the text as reasons).
- **Always remove the file if it exists** (best-effort, guard `OSError`) before returning.
- Add a `DBOS.logger.info` (or module logger) line recording the harvested outcome (so a
  live run is debuggable without container spelunking).

**4c. The agent-Reviewer step** (replaces `reviewer_decide_step`):
```python
@DBOS.step()
def reviewer_agent_run_step(
    run_id: str, reviewer_model: str, iteration: int,
    prd_text: str, idea: str, workspace: str, vkey: str | None,
) -> dict:
    ...
```
- **Forced short-circuit FIRST** (read `_FORCE_REVISIONS_ENV` inside the step, exactly as the
  old `reviewer_decide_step` did): if set to N, return
  `{"status":"completed", "outcome": "changes_requested" if iteration <= N else "approved",
  "reasons": "<forced revision marker>" if changes else None,
  "prompt_tokens":0,"completion_tokens":0,"total_tokens":0,"cost_usd":0.0}` — **no adapter
  resolution, no agent run, no cost** (this is what keeps `loop-run`/`loop-crash`/the offline
  tests LLM-free and is why `team_run` stays openhands-free at import).
- **Real mode** (no env): build the instruction (`_build_review_instruction(prd_text, idea)`);
  `task = AgentTask(instruction=…, workspace_dir=workspace, model=reviewer_model,
  llm_api_key=vkey)`; resolve `"openhands-docker"` vs `"openhands"` from
  `get_settings().agent_sandbox_mode` (same selection the Engineer uses);
  `result = adapter.run(task, on_event=make_run_event_sink(run_id))`. Collect
  `usage = {prompt_tokens, completion_tokens, total_tokens, cost_usd}` from `result`.
  - If `result.status != "completed"` (failed / over_budget) → return
    `{"status": result.status, "outcome": None, "reasons": None, "error": result.error, **usage}`
    (the workflow body handles the terminal case — symmetric with the Engineer).
  - Else → `verdict = _harvest_verdict(workspace)`; return
    `{"status":"completed", "outcome": verdict["outcome"], "reasons": verdict["reasons"], **usage}`.

**4d. The Reviewer branch in `run_graph`** (Task 2's reviewer path). After `mint_vkey_step`:
```python
verdict = reviewer_agent_run_step(run_id, node["model"], n, prd_text, idea, workspace, vkey)
delete_vkey_step(run_id, vkey)
if verdict["status"] == "over_budget":
    if verdict["total_tokens"] or verdict["cost_usd"]:
        # distinct reviewer cost key (see below)

    close_invocation_step(run_id, current, n, "stopped", "over_budget")
    return _finalize_over_budget(run_id, pm_document_id)
if verdict["status"] != "completed":
    close_invocation_step(run_id, current, n, "failed", None)
    mark_run_failed_step(run_id)
    DBOS.logger.error(f"run_team reviewer failed run_id={run_id}: {verdict.get('error')}")
    return {"run_id": run_id, "status": "failed", "document_id": pm_document_id, "error": verdict.get("error")}
# completed: meter the reviewer (only if it actually spent — forced mode is 0), then route on the verdict.
if verdict["total_tokens"] or verdict["cost_usd"]:
    persist_reviewer_cost_step(run_id, node["model"], verdict, n)
close_invocation_step(run_id, current, n, "done", verdict["outcome"])
reviewer_feedback = verdict["reasons"]
outcome = verdict["outcome"]
if apply_budget_hook(run_id, node_id=current, iteration=n):
    return _finalize_over_budget(run_id, pm_document_id)
current = next_node(edges, current, outcome)
```
- Gating the reviewer cost write on non-zero usage means the **forced path writes no cost
