# P0.4a — The 2-Node Skeleton Run (PM → Engineer, one DBOS workflow)

> This is the **first of two prompts** for P0.4. P0.4a builds and proves the 2-node run end-to-end on the happy path. **P0.4b (next prompt) adds the deliberate-crash + resume proof** (`make skeleton-crash`). The architecture you build here **must already be crash-safe** (idempotent ship, coarse agent step) — P0.4b only adds the test that kills the process mid-run and asserts it. Do **not** build the crash harness in this prompt, but **do** build the idempotency that makes it pass, and unit-test that idempotency now.

---

## Objective

Assemble the existing layers (gateway, documents, OpenHands adapter) into a single durable **DBOS workflow** that runs a fixed two-node team — a **PM node** (direct LLM via the gateway) that writes a mini-PRD as a versioned `Document`, then an **Engineer node** (OpenHands adapter) that reads that PRD and ships one trivial feature **into a local git repo** as a single, idempotent, tagged commit. Drive it via HTTP and prove the happy path with `make skeleton-run`.

**Locked design decisions you are implementing (do not re-litigate):**
- **Decision 1 (agent-run crash durability = restart + idempotent ship).** The agent `run()` lives inside **one coarse `@DBOS.step`** — do **not** try to checkpoint inside OpenHands' loop (it would break the adapter boundary). On a crash inside that step, DBOS re-runs the whole step (the agent runs again); we make the **outcome** idempotent instead: the Engineer's "ship" is a **git commit dedup'd by a deterministic tag `ship-{run_id}`**. Re-running the agent overwrites files harmlessly; the ship happens exactly once. (The crash itself is exercised in P0.4b; here, unit-test the ship idempotency.)
- **Decision 2 (agent metering = post-run telemetry).** After `conversation.run()` returns, the adapter reads OpenHands' **own accumulated usage** and returns it as **engine-neutral fields on `AgentRunResult`**; a control-plane step writes **one `CostRecord` per agent invocation**, idempotent on `{run_id}:agent-cost`. **Do not** register a process-global litellm callback (there is only one `litellm` in the process, shared by the gateway and OpenHands — a global hook would also fire for gateway calls). Fallback to a gateway-owned litellm success-callback **only if** post-run telemetry isn't cleanly reachable (verify first; report which path you used and why).
- **Model split:** PM node = cheap `settings.default_model`; Engineer node = a capable slug (default `openrouter/openai/gpt-4o-mini`, overridable via `TVASHTR_AGENT_MODEL` — same env var the agent-smoke uses). Same single `OPENROUTER_API_KEY`, different slug — never a parallel key path.
- **Orphan-`Document` fix (fold in here):** today `create_document` then `add_version` are two transactions; a crash between them strands an empty `Document`. Add a single **atomic** helper that creates the document **and** its first version in **one transaction**, idempotent on the version key, and use it for the PM node. Retrofit `doc_writer.persist_step` to use it too, then re-verify the P0.2 path still works.

## Constraints

- **Stack:** DBOS Transact 2.23.0, LiteLLM (via the gateway only), OpenHands SDK 1.28.1 (via the adapter only), SQLAlchemy 2 + Alembic, FastAPI, Python 3.12 / uv. Postgres 16.
- **Standing conventions (load-bearing — violating any is a failure):**
  1. **At-least-once-safe writes.** Every side-effecting DB write inside a `@DBOS.step` must be idempotent on a deterministic key derived from `DBOS.workflow_id` (check-by-key → insert → catch `IntegrityError` → re-read). Applies to every new write you add. UPDATEs keyed by PK are naturally idempotent.
  2. **Boundary discipline.** Only `gateway/gateway.py` imports `litellm`; only `engines/openhands_adapter.py` imports `openhands.*`. New code depends on Tvashtr-owned types only. **App startup and the offline test suite must NOT import `openhands.*`** — any module that constructs `OpenHandsAdapter` must import it **lazily** (inside the function), exactly as `scripts/smoke_agent.py` does.
  3. **Single key source.** One `OPENROUTER_API_KEY` for gateway, agent SDK, and scripts.
  4. **Verify fast-moving SDKs against the installed package before wiring** (see the explicit verification list below). Make observed behavior the acceptance criterion; record any deviation.
- **Do NOT touch / must keep green:** `hello_durable` + `spike_hello_events`; the internals of `gateway`, `metering`, `documents`, `engines` (extend, don't rewrite — the one allowed edit is adding the atomic doc helper and the `AgentRunResult`/adapter usage fields); existing migrations `0001`–`0003`; the `crash-demo`, `smoke`, `agent-smoke`, `test`, `lint` targets must all still pass. Leave the untracked `Design System/` folder alone.
- **Separate pure logic from durable wrappers** (so it's unit-testable without DBOS): put the ship logic and the graph builder as **plain functions**, and have thin `@DBOS.step`s call them — mirroring how the gateway is a pure function that `doc_writer`'s steps wrap.

The run is **driven by these rows** (§8 below), not by hardcoded constants — this is the seed of "the team is authored."

### 7. Ship logic (pure function) — `control_plane/shipping.py`
Add `idempotent_ship(workspace_dir, run_id) -> dict` using `git` via `subprocess` (no extra deps), implementing Decision 1's idempotent ship:
- If tag `ship-{run_id}` already exists (`git -C <ws> rev-parse --verify refs/tags/ship-{run_id}`): return `{"sha": <existing>, "tag": ..., "created": False}`.
- Else: `git -C <ws> add -A`; if there are **no** staged changes (`git diff --cached --quiet`), raise a clear error (the agent shipped nothing); else `git -C <ws> commit -m "Ship: {run_id}"`, then `git -C <ws> tag ship-{run_id}`, and return `{"sha": <new>, "tag": ..., "created": True}`.
- Also add `init_workspace_repo(workspace_dir) -> None`: idempotently `git init` the workspace if `.git` is absent, set **repo-local** `user.email`/`user.name` (so commits work without global git config), and make an initial empty commit (`git commit --allow-empty -m "init"`). Idempotent (skip if `.git` exists).

### 8. The workflow + steps — `control_plane/team_run.py`
A single `@DBOS.workflow def run_team(idea: str)` with `run_id = DBOS.workflow_id` (which equals `str(runs.id)` — see §9). It loads the Run's team graph and reads the PM and Engineer node configs from the rows (do not hardcode models/engine). Steps, each idempotent per the conventions:

1. **`pm_step(run_id, idea, pm_model)`** — build a PM prompt that instructs a concise mini-PRD which **restates the exact required file path and exact required contents verbatim** plus one sentence of context; call the gateway with `pm_model`; `record_cost(..., idempotency_key=f"{run_id}:pm-llm")`; persist the PRD via `create_document_with_initial_version(..., idempotency_key=f"{run_id}:pm-prd-v1", created_by="agent:pm")`; set `runs.pm_document_id` (idempotent UPDATE). Return `{"document_id": ..., "prd_text": ...}`.
2. **`engineer_setup_step(run_id)`** — `make_local_workspace(run_id)` then `init_workspace_repo(workspace)`. Return the workspace path.
3. **`engineer_run_step(run_id, prd_text, workspace, eng_model)`** — the **one coarse step** wrapping the agent. Build `AgentTask(instruction=<“read this PRD and create exactly the file it specifies with exactly the specified contents; do not add extra files” + the PRD>, workspace_dir=workspace, model=eng_model)`; run `resolve_adapter("openhands").run(task, on_event=make_run_event_sink(run_id))`. Return a JSON-able dict: `status`, `files_changed`, and the neutral usage numbers (`prompt_tokens`/`completion_tokens`/`total_tokens`/`cost_usd`). **Do not** commit or write cost here.
4. **`persist_agent_cost_step(run_id, eng_model, usage)`** — `record_agent_cost(..., idempotency_key=f"{run_id}:agent-cost", model=eng_model, **usage)`.
5. **`ship_step(run_id, workspace)`** — call `idempotent_ship(workspace, run_id)`; set `runs.ship_commit_sha`/`runs.ship_tag` (idempotent UPDATE). Return the ship dict.
6. **`finalize_run_step(run_id)`** — set `runs.status="completed"` and `runs.cost_total_usd = SUM(cost_records.cost_usd WHERE workflow_id=run_id)` (idempotent UPDATE/aggregate).

The workflow body orchestrates: pm → setup → engineer_run → persist_cost → ship → finalize, and returns a summary dict (`run_id`, `document_id`, `ship_sha`, `ship_tag`, `cost_total`). If the engineer step returns `status != "completed"`, mark the run failed and surface the error (don't ship).
