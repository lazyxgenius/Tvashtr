# `/goal` — P1.8d-fix1: authoring canvas infinite render loop (+ Playwright self-sign-off)

> **Context:** P1.8d (`feat/p1.8d-topology-editing` @ `da40105`, unmerged) hangs the browser the moment a team is selected/authored — a frozen main thread ("Maximum update depth exceeded"). Root cause is identified (below). This is a small FE fix on the SAME branch; `main` stays at `63105b5` until it's green. **Run under `--dangerously-skip-permissions`** so the stack bring-up + Playwright MCP calls don't prompt.
>
> **Root cause (already diagnosed — verify, then fix):** in `frontend/src/App.tsx` the `<TeamCanvas>` `tasks` prop is `tasks={authoring ? [] : tasks}`. `authoring` is `runId === null` (true whenever a team is selected with no active run), so `[]` is a fresh array literal every render. `TeamCanvas`'s in-place node-refresh effect lists `tasks` in its dependency array (`[graph, run, workflowStatus, tasks, flags, setNodes]`), so the new `[]` each render re-fires the effect → `setNodes(...)` → re-render → new `[]` → infinite loop. The effect early-returns when `graph` is null, which is why an empty canvas doesn't hang but loading a real team does.

---

## Outcome
The editable canvas renders an existing multi-node team (e.g. "My team") without hanging the browser — no infinite render loop, no "Maximum update depth exceeded". A regression test reproduces the loop (fails on the current branch) and passes after the fix; the scripted e2e is hardened to fail on this class; and **Claude Code self-signs-off the visible surface in a real browser via the Playwright MCP** (screenshots captured), so no human stack bring-up is needed.

## Fix
1. In `App.tsx`, pass a **stable** empty array in authoring mode: a module-level `const EMPTY_TASKS: HumanTask[] = [];` referenced at the call site — `tasks={authoring ? EMPTY_TASKS : tasks}`.
2. **Scan for siblings:** grep `App.tsx` (and the other canvas/panel components) for inline array/object literals or inline-constructed values passed as props that land in a `useEffect`/`useMemo`/`useCallback` dependency array. Stabilize any found (module constant or `useMemo`) and **report each**.
3. (Optional, low-risk only) make `TeamCanvas`'s in-place refresh effect resilient — its `setNodes` updater returns the *same* node object when the derived `data` is unchanged so React can bail. Don't over-refactor; #1 is the actual bug.
