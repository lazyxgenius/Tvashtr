# /goal — P1.8b slice: the team library / multiple persistent teams

> Architect: Tvashtr-27. Slice of P1.8b (the prompt-driven rebuild's authoring FE). Builds on

## Outcome (the one thing this milestone delivers)

Replace the **singleton-by-name** persistent team with **first-class, multiple persistent teams +
a drop-and-edit template library**. The user goes from one implicit "My team" to a **managed shelf
of their own teams**, each created from a starter preset, independently editable (the existing
prompt/model node panel) and runnable (the existing clone-on-launch). This is where *"the team is
mine"* (the §1 differentiator) first becomes visible. Backend (a discriminator + the multi-team
data layer + endpoints) **and** the FE (a left teams rail + a template picker) ship together in this
one slice, smoke-testable end-to-end: **create a team from a template → edit a node → see it in the
rail → run it → delete a team.**

## Locked design — decided from §1 vision + the Tvashtr-25 pivot (do NOT re-open)

- **D1 — first-class identity = a discriminator on `team_graphs`; templates stay CODE.** Add an
  additive `team_graphs.is_library` (boolean, NOT NULL, default false) — migration `0013`. The
  user's library teams are the `is_library = true` rows; the team list is `WHERE is_library`. The
  `teams.py` builders (`build_two_node_team` / `build_review_loop_team`) **are** the curated
  template library (code, not rows); "drop a preset" = materialize a builder into a new
  `is_library` team. User-authored/shareable *templates* are the Phase-4 marketplace — NOT this
  slice.
- **D2 — operation set: list / create-from-template / select-to-edit / run / delete.** Rename is
  DEFERRED (a team is named at creation, so it's never "Untitled"; log the deferral). The library
  is **never empty** — seed one team if the library has zero (server-side), so the canvas is never
  blank (the §13 S2 anti-dead-zone posture).
- **D3 — a persistent left "teams" rail beside the ONE canvas; no second window, no router.** The
  canvas stays the persistent center; the left/right slots already swap by context. Authoring slot
  layout `[ teams rail | canvas | node-edit panel ]`; run slot layout `[ tasks drawer | canvas |
  verdict panel ]` (unchanged). The Single / A-B toggle is untouched and orthogonal. "Editing a
  team" is the existing click-a-node → right-side prompt/model panel ON the same canvas — there is
  no separate editor window.
- **D4 — migration is non-destructive: "My team" is PROMOTED, builders/clone byte-intact.** The
  `0013` data step sets `is_library = true` on the existing `"My team"` row (no-op if absent) so
  the user's P1.8b-1 edits carry forward as their first library team. The builders +
  `clone_team_graph` never set `is_library` → it defaults false → clone snapshots, A/B graphs, and
  smoke graphs are automatically non-library and can NEVER pollute the list. The singleton helper
  (`get_or_create_persistent_team` / `PERSISTENT_TEAM_NAME`) RETIRES.

- New migration `backend/alembic/versions/0013_team_graph_is_library.py` (the ONLY new migration):

## Backend — `teams.py` + `routers.py`

In `teams.py`:
- **Keep `build_two_node_team`, `build_review_loop_team`, `clone_team_graph` BYTE-IDENTICAL.**
- **Retire** `get_or_create_persistent_team` + `PERSISTENT_TEAM_NAME` (replaced by the helpers
  below). Removing them is expected and correct.
- Add a small **template catalog** (the curated library), e.g. an ordered list mapping a stable
  `template` key → `(display name, description, builder)`:
  - `"two_node"` → name `"PM → Engineer"`, desc "A PM writes the spec; an Engineer builds and
    ships it. No review step." → `build_two_node_team`.
  - `"review_loop"` → name `"PM → Engineer ↔ Reviewer"`, desc "Adds a Reviewer that runs the tests
    and loops back for fixes until it passes (or the cap trips)." → `build_review_loop_team`.
- Add `create_team_from_template(template_key, name) -> str`: call the byte-intact builder, then
  set the new row's `name = <user name>` and `is_library = True`; return its id. (Build then flip —
  the builder stays untouched.)
- Add `list_library_teams() -> list[...]` (the `is_library = true` rows, ordered `created_at, id`)
  and `seed_library_if_empty() -> None` (if zero library teams exist, create one from
  `"review_loop"` named `"My team"` — so a fresh DB / a never-opened singleton still lands ≥1).
- Keep these pure-DB + openhands-free at import (same discipline as the builders).

In `routers.py` — replace the three singleton endpoints + add the library surface. **The A/B
section (`create_ab_runs`, `get_ab_comparison`, `_AB_CONFIGS`, `_TEAM_BUILDERS`) and `create_run` /
the clone-on-launch path stay BYTE-IDENTICAL** (the FE just passes the selected team's id to the
existing `POST /api/runs {team_graph_id}`).
- `GET /api/templates` → `{ "templates": [ { "template", "name", "description" }, … ] }` from the
  catalog (the picker reads this; the FE does not hardcode the list).
- `GET /api/teams` → calls `seed_library_if_empty()` then returns `{ "teams": [ {
  "team_graph_id", "name", "created_at", "node_count" }, … ] }` (library teams only). The list is
  never empty.
- `POST /api/teams` (body `{ "template": str, "name": str }`) → `create_team_from_template` →
  return the new team's summary (and the FE then fetches its graph, OR include the graph in the
  response — your call). 400 on an unknown `template`.
- `GET /api/teams/{team_id}/graph` → the team's nodes + edges in the **same** shape as the retired
  `GET /api/team/graph` (reuse `_node_base_dict` / `_edge_to_dict`; include `prompt`; no run
  state). 400 on a malformed id; 404 if the team isn't a library team (so snapshots/A-B graphs
  aren't readable here).
- `PATCH /api/teams/{team_id}/nodes/{node_id}` → the rescoped node-prompt/model edit. Validate the
  node belongs to `team_id` **and** that team is a library team; keep the existing guards: 400
  bad-uuid, 404 off-team / non-library, 409 gate/terminal. (Same `UpdateTeamNodeRequest{prompt,
  model}`.)
- `DELETE /api/teams/{team_id}` → delete a library team (validate `is_library` first → 404 if not,
  so you cannot delete a snapshot/A-B graph via this endpoint). The FK cascade drops its
  nodes/edges. Safe — `Run.team_graph_id` points at the clone snapshot, never the library team.

## Frontend — `api.ts` + `App.tsx` + a new teams-rail/picker component

- `api.ts`:
  - Re-scope `getTeamGraph` to take a team id → `GET /api/teams/{id}/graph`; re-scope
    `updateTeamNode(teamId, nodeId, prompt, model)` → `PATCH /api/teams/{teamId}/nodes/{nodeId}`.
    `runTeam(teamGraphId)` is UNCHANGED (it already POSTs `{ team_graph_id }`).
  - Add `getTeams()`, `getTemplates()`, `createTeam(template, name)`, `deleteTeam(teamId)` + the
    types `TeamSummary { team_graph_id, name, created_at, node_count }` and `Template { template,
    name, description }`.
- `App.tsx`:
  - New state `teams: TeamSummary[]` + `currentTeamId: string | null`. On mount: `getTeams()` →
    pick the first as `currentTeamId` → load its graph. `currentTeamId`/`teams` persist across a
    run (only the run-scoped state resets — `resetRunState` must NOT clear them).
  - The authoring-side **left slot** renders a new `<TeamsRail>` (the list of `teams`, the current
    one highlighted; a `+ New team` action; a per-row delete with a confirm). Selecting a team →
    set `currentTeamId`, clear `selectedRole` (close the node panel), load that team's graph. In
    **run** mode the left slot stays the `TasksDrawer` (unchanged).
  - `+ New team` opens the **template picker** (from `getTemplates()`): show each preset's
    name+description, take a name, `createTeam` → set the new team current + refresh the list +
    load its graph. Steer the picker toward the existing panel/drawer aesthetic (an inline
    expander or the right-panel slot), NOT a heavy modal overlay — leave the exact rendering to
    the build + the operator's eyeball.
  - `handleRunTeam` runs `currentTeamId` (clone-on-launch); `handleEditTeam` returns to the current
    team's authoring view with the rail restored. The `TeamCanvas` + `TeamNodePanel` keep their
    behavior (they already render one team / edit one node) — thread the current team's id through
    where they call `getTeamGraph` / `updateTeamNode`.
  - Because the library is server-seeded non-empty, the FE may assume ≥1 team (a dedicated
    empty-state is optional; a deleted-last-team re-seeds on the next fetch — acceptable v1
    behavior; note it).
- Reuse the existing design tokens/components (`tv-panel`, `tv-btn`, the drawer styling); additive
  CSS only; no new dependency.
