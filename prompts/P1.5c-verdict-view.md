## Context (current state — verified on disk)

  (`control_plane/team_run.py` `run_graph`) closes the Reviewer's invocation each round with
  `close_invocation_step(..., outcome=verdict["outcome"])` (`approved` / `changes_requested`); the
  Engineer closes with `"built"`, the PM with `"prd_written"`, gates with their resolution, terminals
  with `"shipped"`/`"stopped"`. `AgentInvocation` (table `agent_invocations`, migration `0008`) has an
  `outcome: Text|None` column keyed on `(run_id, node_id, iteration)`. **This step only READS it.**
- **The reasons are NOT queryable** — `close_invocation_step` writes only `status` + `outcome` (the
  label), not `verdict["reasons"]`. The reasons live in the DBOS step output, not in a clean table.
  So **this step surfaces the per-round LABELS only**; the reasons ("why B sent it back") arrive with
  §14.2's A/B work (migration `0010` will add a reasons column there). Update the stale NOTE to say so.
- **The graph endpoint already has every invocation row in hand.** `routers.py` `get_run_graph`
  fetches all `AgentInvocation` rows for the run and computes `latest_by_node` (max iteration per
  node) for the per-node `status`/`iteration` it already returns. Current per-node serialization:
  ```python
  invocations = (
      session.execute(select(AgentInvocation).where(AgentInvocation.run_id == run_id))
      .scalars().all()
  )
  latest_by_node: dict[str, AgentInvocation] = {}
  for inv in invocations:
      key = str(inv.node_id)
      if key not in latest_by_node or inv.iteration > latest_by_node[key].iteration:
          latest_by_node[key] = inv
  # ... per node dict carries: id, role_name, kind, model, engine, position, config,
  #     "status": latest_by_node[...].status if present else "idle",
  #     "iteration": latest_by_node[...].iteration if present else 0,
  ```
- **The FE data flow:** `App.tsx` polls `getGraph(runId)` → `graph` (every 1800ms while non-terminal);
  when a node is selected it renders `<SidePanel selectedRole=… iteration={graph?.nodes.find(n =>
  n.role_name === selectedRole)?.iteration ?? 0} runId=… run=… workflowStatus=… onClose=… />`.
  `SidePanel` is deliberately **graph-free** (it receives the `iteration` scalar, not the graph).
  Its reviewer branch renders `ReviewerView`:
  ```tsx

    return (
      <div className="tv-scroll">
        <p className="tv-panel-note">The reviewer reads the engineer's work against the spec,
          then either approves it or sends it back for another round of changes.</p>

  ```

  verdict history is exactly what belongs there.
