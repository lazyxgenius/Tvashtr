# P1.7a — Live-document steering: the backend seam (offline-proven)

## Objective (the one thing this milestone delivers)
Make the in-flight PRD a **live steering surface**: a human edit to the PRD becomes a new `DocumentVersion`, and the running agents pick it up on their **next read** (J3 — "the change propagates to the relevant agents on their next read; the document, not agent memory, is the source of truth"). This is the BACKEND seam only — proven by the offline suite. The TipTap editor + lock-aware UI + the live visual smoke are P1.7b (a separate slice); **build NO frontend here.**

Two changes:
1. **A save-edited-PRD endpoint** — `POST /api/documents/{document_id}/versions` appends a new version over the existing `add_version` service helper.
2. **The executor re-sources the PRD live** — at each agent-node entry the Engineer/Reviewer read the **latest** `DocumentVersion` via a **recorded `@DBOS.step`**, instead of the PM's once-captured `prd_text` snapshot.

## Tasks (ordered)
1. **Service helper** — in `documents/service.py`, add `get_latest_version(document_id: uuid.UUID) -> DocumentVersion | None` (the row with the max `version_no`, its own `session_scope`). Keep it small and transaction-safe like the others.
2. **Save-version endpoint** — in `routers.py`, add `POST /api/documents/{document_id}/versions` taking a Pydantic body `{ "content": str }`. 404 if the document doesn't exist. Otherwise call `add_version(document_id, content, created_by="human", idempotency_key=f"human-edit:{document_id}:{uuid4().hex}")` (a fresh key per request → each POST is a NEW version) and return the new version (`version_no`, `content`, `created_at`, `document_id`). Mirror the existing `GET /api/documents/{id}` router/Pydantic style.
3. **Recorded re-read step** — in `team_run.py`, add `@DBOS.step()` `read_latest_prd_step(run_id: str) -> str` (or `-> {version_no, content}`): look up `Run.pm_document_id`, then `get_latest_version(...).content`. The PM always writes v1 before any agent node, so this resolves; if `pm_document_id`/version is unexpectedly absent, **raise a clear error** (do NOT silently build from empty). It MUST be a `@DBOS.step` (the determinism requirement — see below).
4. **Wire the re-source** — in `run_graph`, at **each agent-node entry** (the Engineer node AND the Reviewer node, **every iteration**), call `read_latest_prd_step(run_id)` and pass its result as the `prd_text` argument to `engineer_run_step` / `reviewer_agent_run_step`, instead of the PM-captured snapshot. The workflow-local `prd_text` from the PM may remain only for the return/finalize dict if needed. The `idea` argument stays the snapshot. Keep `pm_step` and both agent-step bodies otherwise byte-identical (they still receive a `prd_text` string — they don't care where it came from).
5. **Tests** (offline, genuine, non-vacuous):
   - **Endpoint** — `POST /api/documents/{id}/versions` creates `version_no = prev+1` with the posted content; 404 on a missing document id.
   - **Read step** — `read_latest_prd_step` returns the LATEST version's content (write v1, add v2, assert it returns v2's content).
   - **The steering proof (the keystone)** — extend the `test_review_loop` pattern: drive the **real** `run_team` on the forced-revision path with openhands stubbed; **between Engineer iteration 1 and iteration 2, append a new PRD `DocumentVersion`** (via `add_version` on `Run.pm_document_id`); assert the `prd_text` the iteration-2 Engineer step receives is the **NEW** content, not the PM's original. Prove non-vacuity by mutation in your review (revert the re-source → this test must FAIL).
   - **Structural** — assert `read_latest_prd_step` is a DBOS step (e.g. it carries the step wrapper / is registered), so the determinism guarantee is enforced by a test, not just intent.

## Determinism (the reason the re-read is a recorded step — get this right)
A crash mid-run must resume reading the **same** PRD version the original execution saw, even if the human edited the PRD again after the crash. Because `read_latest_prd_step` is a `@DBOS.step`, its `{version_no, content}` is recorded on first execution and **replayed verbatim** — each agent-node entry's read is a distinct recorded step, so the resumed walk reproduces exactly the versions used. A bare (non-step) read would re-query the live table on replay and could pick up a newer edit → non-deterministic resume. This is the whole point; do not make it a plain function.
