# P1.4a — LiteLLM proxy stand-up + route the agent's LLM through it (with a container-reachability de-risk)

## Objective
Stand up a **LiteLLM proxy** as a `docker-compose` sibling to Postgres, and route the **OpenHands agent's own LLM calls** through it in **both** sandbox modes (`local` and `docker`), proving the agent reaches the proxy **from inside its container** via `host.docker.internal` — WITHOUT changing metering, budget enforcement, or the offline/no-key behavior. This makes the proxy the physical chokepoint the agent's traffic flows through. The per-run virtual-key budget (the mid-loop spend cutoff) is the follow-up step P1.4b — NOT this step.

## Context (where it fits + current state on disk)
- Phase 1, **P1.4** (the agent-internal spend chokepoint), decomposed into **4a** (this: plumbing + reachability proof) and **4b** (per-key budget cutoff). Lands before P1.5's long agent work.
- **The agent's LLM is built identically in BOTH adapters, with NO `base_url`** — OpenRouter is reached implicitly via the `openrouter/*` model slug:
  - `backend/tvashtr/engines/openhands_adapter.py` (local), inside `OpenHandsAdapter.run()`:
    ```python
    api_key = os.environ.get("OPENROUTER_API_KEY")
    ...
    llm = LLM(model=model, api_key=api_key, temperature=0.0, usage_id="tvashtr-agent")
    ```
  - `backend/tvashtr/engines/openhands_docker_adapter.py` (docker), inside `OpenHandsDockerAdapter.run()`: the SAME construction. Its comment is load-bearing: the LLM config (incl. the key) is **serialized into the agent and the calls are made by the agent-server *inside the container*** ("The container needs egress to OpenRouter"). That container runs on Docker's **default bridge network, not the compose network** (it is started ad-hoc by `DockerWorkspace` and reaped by image in `engines/docker_runtime.py`).
- `backend/tvashtr/control_plane/team_run.py` — `engineer_run_step` resolves `"openhands-docker"` vs `"openhands"` from `get_settings().agent_sandbox_mode`. **Do not change the workflow or this selection.**
- `backend/tvashtr/gateway/gateway.py` — the **only** `litellm` importer; the PM/direct path; a pure request→result function. **Do NOT route the gateway through the proxy in 4a.**
- `backend/tvashtr/control_plane/teams.py` — **read it** to get the EXACT PM + Engineer model slugs `build_two_node_team` seeds; the proxy config must route them.
- `backend/tvashtr/config.py` — `Settings`: `default_model = "openrouter/meta-llama/llama-3.1-8b-instruct"`, `model_fallbacks = ["openrouter/google/gemini-flash-1.5", "gpt-4o-mini"]`, `agent_sandbox_mode` (default `docker`), `agent_server_*`.
- `docker-compose.yml` — Postgres only (host `5433` → container `5432`); backend/frontend are local processes (killable-PID requirement).
- `Makefile` — `db-up` (compose up + wait-healthy), `backend` (bare uvicorn, KEEP killable), `skeleton-run-docker` (`TVASHTR_AGENT_SANDBOX=docker`), demos pin `local`.
- `.env.example` — provider keys (`OPENROUTER_API_KEY`, etc.).
- Tests live under `backend/tests/`; the import-boundary test is `tests/test_registry.py`; the offline suite is **61 tests**; `make test` needs `make db-up && make migrate` first; `make lint`/`fmt` scope ruff to `backend/`.

## Constraints
- **Stack/conventions:** Python/FastAPI, pydantic-settings `Settings`, `uv`, ruff. Match the gateway's posture (quiet, telemetry off, no phone-home).
- **DO NOT TOUCH:** `run_team`/the workflow body + its steps; `gateway/*`; `metering.py`; `models.py` (NO migration); `engines/base.py` (the `EngineAdapter` contract); `engines/registry.py`; `engines/docker_runtime.py` (reaping); `_read_usage` / `_pull_workspace` / the event-handling code / the `AgentRunResult` shape; the frontend; the existing demos' `TVASHTR_AGENT_SANDBOX=local` pins. The **only** change inside the two adapters is the `LLM(...)` construction, behind the opt-in flag.
- **Metering is unchanged in 4a** — the agent's `CostRecord` still comes from OpenHands telemetry (`_read_usage`); the proxy returns usage in its responses so this keeps working. (The metering-collapse is staged for later.)
- **Opt-in + fallback:** when the proxy flag is OFF (the default), the adapters build the LLM EXACTLY as today. Offline tests and no-key demos must be byte-for-byte unaffected.

### Task 3 — route the agent's LLM through the proxy (both adapters), behind the flag

- **Else:** keep the EXACT current construction (`api_key = OPENROUTER_API_KEY`, bare `model`).
- Minimal + clearly commented; touch nothing else in the adapters. **Do NOT** route the gateway through the proxy.
