## Outcome

The team canvas becomes **fully editable**: the user can **add, delete, and rewire nodes and edges** to author an arbitrary team graph from scratch (or by reshaping a template), with **live holistic graph-validity** gating runs, and **node positions persist**. An existing library team and all three code templates (`two_node`, `review_loop`, `thinker_chain`) still run **unchanged**.

Backend gains node/edge **CRUD** + a **pure `validate_graph`** function + a **run-start validity guard**. Frontend turns on `nodesConnectable`, adds a **node palette**, **edge-role authoring**, the per-decision-node **emit-contract**, and the **invalid-graph surface**.

## Design spec (settled — implement faithfully)

### 1. Schema — NO migration
The existing schema already supports this. `agent_nodes.position` (JSONB, NOT NULL, default `{}`) is the home for durable canvas layout — persist `{"x":…,"y":…}` there. Edges are representable with existing columns (`source_node_id`, `target_node_id`, `edge_type`, `conditions`). Node creation fills the only NOT-NULL-no-default columns from the request (`role_name`, `kind`; edges: `source`/`target`/`edge_type`). **Migration head stays `0013`.** Do **not** add a migration.

### 2. Executor — UNTOUCHED
The graph-driven executor already runs *any* graph rows it is given. Authoring new graphs needs **zero** executor change. `backend/tvashtr/control_plane/team_run.py` — the walk (`run_graph`) and the routers (`next_node` / `escalation_target` / `loop_limit_for` / `node_emits_outcome`) — is **NOT modified** (target evidence: `git diff main -- backend/tvashtr/control_plane/team_run.py` is **EMPTY**). The run-start validity guard lives in `routers.py` `create_run`, **not** in `team_run.py`.

### 3. Graph validity — the gate (a pure, importable function + a server guard)
Add a pure, importable `validate_graph(nodes, edges) -> {errors: [...], warnings: [...]}` (structured, each item carries a human message + the offending node/edge id). **Strictness = block only un-runnable graphs; warn on the rest.**

**BLOCK (these make a run crash / hang / loop forever / stop with no outcome):**
1. **Exactly one root** — exactly one node with no incoming edge. Zero roots (no entry) or two+ roots (ambiguous entry) → block. (The executor is single-entry.)
2. **The root is a thinker** (`kind == "completion"`). The root writes the shared spec every worker reads; a worker/gate/terminal root breaks the spec-first spine. (This is today's PATCH-409 lifted to the whole graph. It also makes "a thinker runs before every worker" automatic — do **not** add that as a separate rule.)
3. **Enforced termination** — every cycle's back-edge carries a `loop_limit` (`conditions.loop_limit`), **and** every node reachable from the root can reach a terminal (`kind == "terminal"`). This single check subsumes "no dead-end non-terminal on a live path" and "the loop/escalation is well-formed."

**WARN (runnable — surface, do not block):**
- **Orphan / unreachable node** — exists but the walk never reaches it.

**Do NOT police** (out of scope, by design): prompt↔capability coherence (semantic, unreliable, and capability is the user's explicit switch); unmatched outcome labels (the executor's existing catch-all safe-default already routes unmatched emissions to rework — runtime handles it).

**Server-authoritative:** `create_run` re-validates the (cloned) graph and **refuses an invalid graph with a 4xx** carrying the structured errors — you cannot launch a broken graph even via the API. The FE mirrors the *same* verdict (shared logic, or a `GET/POST …/validate` endpoint the FE calls) so the live Run-disabled UX never disagrees with launch.

**Acceptance:** unit tests for each block + warn case (mutation-real — read the bodies); the three templates + the seeded `"My team"` all **PASS**; a hand-built invalid graph is refused at `create_run` with its specific error.

### 4. CRUD — backend endpoints (team-scoped, library-guarded)
Reuse the existing `_require_library_team` guard — **only `is_library` teams are editable** (a run snapshot / A-B graph is never CRUD-able via the team API). All endpoints under the team-scoped path (mirror the existing `PATCH /api/teams/{id}/nodes/{id}`).

- **Create node** — body carries `kind` (+ `capability` mapping for thinker/worker as P1.8c does), optional `prompt`/`model`, `position`, and for gate/terminal the `config` (gate: `title`/`description`; terminal: `terminal_kind` ∈ ship|stop). Support **blank** primitives (empty prompt) **and preset** nodes (PM / Architect / Engineer / Reviewer) seeded from the existing `teams.py` prompt constants. Returns the created node.
- **Delete node** — cascades its edges (FKs already `ondelete=CASCADE`). (Safe: runs use cloned snapshots, so deleting a *library* node never touches any past run's `AgentInvocation` rows.)
- **Update node** — the existing `PATCH …/nodes/{id}` (prompt/model/capability) stands; extend only if needed (e.g. to persist `position`, or `config` for a gate/terminal title).
- **Create edge** — body carries `source_node_id`, `target_node_id`, and a **role** that maps to `(edge_type, conditions)` per §6. Validate source/target are on the team (404 otherwise).
- **Delete edge.**
- **Persist position** — on node drag (batch is fine: one endpoint that takes node-id→position, or fold into update node).

New **blank-team creation** (extend the existing create-team path / the rail's New-team picker): a "Blank team" option seeds the **minimal valid skeleton — one root thinker → a Ship terminal (2 nodes, 1 edge)** — never a 0-node canvas (which our own gate rejects).

**Acceptance:** backend tests for create / delete / rewire + the guards (off-team foreign-node 404, gate/terminal handling); each edge **role round-trips to the correct `conditions`/`edge_type`** (forward→`null`; branch→`{when:LABEL}`; loop-back→`{loop_limit:N}`; escalation→`edge_type="escalation"`).

### 5. Palette + blank-team seed (FE)
A small palette tray **on the canvas** (distinct from the left teams rail):
- **Four blank primitives:** blank **thinker** (completion), blank **worker** (agent+openhands), **gate**, and **Ship / Stop** terminals (two chips — `terminal_kind` is a real choice).
- **A thin "role presets" tray:** drop a **pre-filled-but-fully-editable** PM / Architect / Engineer / Reviewer node (seeded from the `teams.py` prompt constants — node-granularity drop-and-edit, the team-granularity version already shipped as the rail picker). This is the answer to the §13-S2 dead-zone at node level — keep it in.

### 6. Edge authoring — the four roles + the close-the-loop gesture + the emit-contract (FE)
The executor distinguishes exactly **four edge roles** by `(edge_type, conditions)` — already verified in `team_run.py`:
- **Forward** — `conditions: null`. "Always go next." (Thinkers always route this way.)
- **Branch** — `conditions: {when: LABEL}`. Only **workers** (verdict-file harvest) and **gates** (resolution = approved/rejected) emit labels; a thinker **cannot** branch in today's executor.
- **Loop-back** — `conditions: {loop_limit: N}` (no `when`). The bounded catch-all rework edge; the bound lives on the **back-edge** (the edge returning to the re-entered node) and caps that node's re-entries.
- **Escalation** — `edge_type: "escalation"`. Invisible to normal routing; taken **only** when a looping worker exhausts its limit. Its **source is the looping worker itself**; target is a gate or Stop. (So a bounded loop and its exhaustion-exit are a structural *pair*.)

**Authoring model:** when the user draws S→T, an inline editor sets the edge's **role in plain language, offering only what S supports** — never raw `{when}`/`loop_limit`/`escalation`:
- **From a thinker** → only **"Then →"** (forward).
- **From a gate** → **"If approved →"** / **"If rejected →"**.
- **From a worker** → **"Then →"**, or **"When it outputs ___ →"** (branch) — the label via a combobox **seeded with the labels already used on that worker** (a second branch reuses the same word → no PASS/Pass drift).
- **When the edge closes a loop** (T is upstream of S) → offer **"Rework loop"**: set the bound N (default 3) **and immediately ask where to go when the limit is hit** (→ a gate or Stop). You **cannot** author a bounded loop without its exhaustion exit — this is what makes termination provable (the §3 hard rule).

The idiom this produces is the safe one already in the templates: **label the proceed-exits; leave the rework loop-back as the catch-all** (e.g. Reviewer "When it outputs PASS → Ship" + a Rework loop back to the Engineer catching everything else — a missing/garbled verdict safely loops, never ships).

**Anti-drift mechanism (the exact bug class that bit Tvashtr-26 — the vanished loop-back arc):** a branch worker's panel shows a derived **emit-contract** ("must output PASS to proceed; anything else reworks") computed **live from its out-edges**, plus a one-click **"write this into the prompt"** that inserts/updates the standardized instruction — **including the verdict-file contract the harvester reads** (mirror today's `REVIEWER_PROMPT`: write the verdict file with the labels + reasons) — templated with the user's labels. Single source of truth = the edge labels; the prompt is kept honest by a button; the contract is impossible to miss. (Do **not** hard-block on prompt wording — make it *visible*.)

### 7. Frontend canvas behavior
- `nodesConnectable` **ON**; wire React Flow `onConnect` / `onEdgesDelete` / `onNodesDelete` → the CRUD endpoints.
- **Live validity:** recompute on every edit (not only at launch). Invalid → **Run greys out** + a per-issue list ("No single starting point — two unconnected entries"; "The Reviewer→Engineer loop has no exit — route to Ship or a gate when the limit is hit") + a red flag on the offending node/edge. **Warnings** (orphans) → a dimmed/dashed node, **Run stays enabled**.
- **Positions persist** on drag; **auto-layout fallback** for empty positions (existing teams carry `{}` today — apply a deterministic layout so nothing stacks at 0,0, then persist real coords on drag / on node create).
- Keep today's per-node prompt/model/capability editing (the right-side panel).

**Scope line (defer → note in §15, do NOT build):** **gate/terminal config editing** beyond drop-time (rename a gate / flip a terminal post-drop — the immediate follow-on); **user-authored custom presets** (save your own — Phase-4); **thinker-as-router** (letting a thinker emit a routing label — needs a NEW executor harvest path for completion output, real executor work outside this wiring slice); the cosmetic `REVIEW_VERDICT.json`→`OUTCOME.json` rename (byte-intact discipline).
