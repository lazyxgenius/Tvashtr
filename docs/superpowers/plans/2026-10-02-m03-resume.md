# M3 — Resume from here — Implementation Plan

> For agentic workers: Native execution (one implementer + the brief's independent review). Steps use `- [ ]`.

**Goal:** a failed / stopped / stalled run picks up from a chosen agent step as a NEW linked run that
carries everything before that step (never re-run, never re-billed) and rebuilds its workspace from a
durable checkpoint (R8).

**Architecture:** every completed agent step records a checkpoint row (diff of the host workspace
against the run's base commit + the walk state + the documents' versions). `POST /api/runs/{id}/resume`
clones the OLD run's snapshot graph (not the library team), copies the carried documents, inserts the
new run (`resumed_from_run_id`, `resumed_from_step`) and starts `run_team`; a new recorded step
(gated on the immutable `resumed_from_run_id`) hands `run_graph` its start node + carried state, and
the workspace is rebuilt from base + the checkpoint's diff. The Activity read shows the old run's
carried lines ("from run #12") and the Carried over state.

**Tech:** FastAPI, DBOS, SQLAlchemy/Alembic (0044), git CLI, React/TS.

**Spec:** prompts/m1-m11.md §4 M3 + R8; Runs canvas › Prob-Stalled, Prob-Failed, Prob-Pick, Prob-Confirm,
Prob-Resumed (+ Live-Home's Resume in Needs you / Running now); boards added for M3 on the same page:
`Prob-ConfirmStalled` (the confirm when the run is still running with a Stalled step: "This stops run #12 and
starts run #13…", "Run #12 is stopped first. What it did stays as it is") and `Prob-HomeFailed` (Needs you's
"Run failed" row keeps View run + Retry and gains Resume).

## Design decisions (from the code map)
1. **Graph:** clone the old run's snapshot with `_copy_graph(..., link_origin=True)` but keep
   `cloned_from_node_id` = the OLD node's `cloned_from_node_id` (the library node) → memory, node
   history and origin ids stay right; one run per snapshot graph (team delete + node_history assume
   it). Old→new node map by `cloned_from_node_id`, falling back to copy order (a dict returned by a new
   `copy_run_graph(old_graph_id) -> (graph_id, {old_node_id: new_node_id})`).
2. **Checkpoint** (`run_checkpoints`, 0044): id, run_id (uuid FK runs CASCADE), invocation_id (FK
   agent_invocations CASCADE, unique), node_id, iteration, base_sha, diff (bytea, NULL when over the
   cap), state jsonb `{iters_by_node, reviewer_feedback, pm_document_id, documents:[{id,name,version_no}]}`,
   created_at. Recorded by `record_checkpoint_step` right after each agent step closes `done`.
   Diff = temp index (`GIT_INDEX_FILE`) `add -A` minus the ship exclusions, `diff --cached --binary
   <base>`; base = greenfield root commit / brownfield `merge-base HEAD <start point>`. Never raises
   (a failure records a RunWarning and a row with diff NULL ⇒ later points unavailable).
   `# ponytail: 20 MB diff cap in a bytea column; object storage if real repos exceed it`.
3. **Runs columns** (0044): `resumed_from_run_id` uuid FK runs SET NULL, `resumed_from_step` int FK
   agent_invocations SET NULL (the chosen step of the old run).
4. **Resume points** of run R (ended failed / cancelled / stalled, or running with a Stalled step):
   R's agent invocations in walk order; point S is available iff S is R's first agent step, or the
   agent invocation just before S has a checkpoint with a diff. Folder runs (`local_snapshot_id`)
   have no points (their source bundle is emptied at clone) → no Resume buttons (noted, Not done).
   Suggested = the failed / stalled step.
5. **Carried state for S** = the checkpoint C of the agent step before S (none ⇒ fresh): iters,
   reviewer feedback, the documents (copied into the new run at create: versions 1..version_no, new
   doc ids, idempotency `{new}:carried:{old version id}`, original created_at), pm_document_id → the
   copy. Start node = new id of S.node.
6. **Workflow:** `run_team` adds `resume = load_resume_step(run_id)` only when the run row has
   `resumed_from_run_id` (read by a plain gate like `local_repo.is_folder_run`) → `run_graph(run_id,
   graph, idea, resume=resume)`; `run_graph` seeds `current/iters_by_node/reviewer_feedback/
   pm_document_id` from it. After `ensure_run_workspace` (+ grounding), `apply_checkpoint(run_id,
   workspace, resume)` (plain fn, idempotent via a marker in `.git/`): reset the fresh branch to
   base_sha (brownfield; fetch the sha if missing), `git apply --binary` the diff. Greenfield: apply
   onto the new root. A failure fails the run readably (`run_failure.CHECKPOINT`).
7. **Stalled-but-running R:** the resume route first stops R with `cancel_run_core` (the Stop path),
   then creates the new run.
8. **Activity** of a resumed run: R's lines up to S (recursively, so a resume of a resume works),
   each with `carried_from: <run number>`; then a `resumed` Run line "Resumed from run #12 at
   Engineer, round 2"; then the new run's own lines (the copied document versions are skipped). Agents
   whose every round is carried: `live_state="carried_over"`, activity "From run #12 · spec v2" /
   "Approved in run #12"; the next looping agent waiting with carried notes: "Round 1 notes carried
   over". `pinned` failed / stalled gain `resume: {invocation_id, label}` + `safe` / `next` copy.
   Run payloads add `number`, `resumed_from: {run_id, number}`.
9. **Routes:** `GET /api/runs/{id}/resume` → `{available, reason, number, next_number, points:[{
   invocation_id, node_id, label, iteration, kind, text, at, cost_usd, state: kept|suggested,
   resumable}], …}` with each resumable point's `kept[]`, `runs_again[]`, `skips_cost_usd`,
   `skips_s`; `POST /api/runs/{id}/resume {invocation_id}` → 201 `{run_id, number}`; 409 when not
   resumable; 404 for another account.
10. **Test hook (LLM-free, for the e2e + live check):** `TVASHTR_FORCE_FAIL_ROLE` +
    `TVASHTR_FORCE_FAIL_ROUND` fail that role's round in a run that is not itself a resume (beside
    `_forced_hang`).

## Review focus
1. A resumed run whose base branch moved since (brownfield / hosted) — rebuilt on the recorded
   base_sha, PR still into base_ref.
2. Resume of a resumed run (#14 from #13 from #12) — carried lines and documents chain correctly.
3. A run recovered by DBOS on another machine mid-resume — the workspace is re-materialized and the
   checkpoint re-applied exactly once.
4. Binary files / deletions / renames in the diff — `git apply --binary` round-trips them.
5. Two Resume clicks (double submit) — the second is refused or yields the same run (409 if R already
   has a resumed run in flight).
