## 1. What just landed — P1.4b (Tvashtr-12)
The agent's runaway-spend cutoff is now real and proven. As-built (full detail in the §17 as-built entry — read it):
- **A per-run LiteLLM virtual key, minted as a durable Control-Plane `@DBOS.step` (`mint_vkey_step`) inside `run_team`** (NOT the HTTP endpoint; NO `Run` column; **no migration**). `max_budget` = the run's **remaining** budget (`cap − running_cost`, after the PM), floored at `1e-6`; **uncapped** when `budget_overridden` or `cap is None`. TTL `30m` (crash-robust floor) + best-effort `delete_vkey_step` after the agent. A new **stdlib-`urllib`-only** `control_plane/litellm_admin.py` (`/key/generate`+`/key/delete`, master-key bearer auth) — imports neither `litellm` nor `openhands` (the boundary holds). `agent_llm_routing` gained `api_key_override` (the vkey becomes the agent's api_key when the proxy is ON; the master key stays the admin/mint credential).
- **Breach → `over_budget`.** `AgentRunResult.status` is now `Literal["completed","failed","over_budget"]` and `AgentTask.llm_api_key` carries the key — **the only two contract edits**. A shared `_is_budget_error(exc)` classifies the proxy's budget error **by message** (not 429 alone — a real rate-limit stays `failed`) without importing litellm; `run_team` routes `over_budget` (checked **before** the generic failed branch) → best-effort partial-cost → `finalize_run_step("over_budget")` (no ship). **P1.2's between-steps gate is KEPT** — the two never both fire (proxy = mid-step cutoff; gate = between-steps).
- **A docker-mode classification bug the live demo caught (the verify-don't-assume lesson, sharpened).** The first `make proxy-budget-demo` ended `failed`, not `over_budget` — the proxy enforced the budget correctly, but in **docker mode** the SDK's `RemoteConversation` **genericizes** the raised exception to `"…Remote conversation ended with error"` (a race in `_get_last_error_detail`), stripping the budget message; it survives on the host **only** in the streamed `ConversationErrorEvent.detail`, which the adapter was dropping. **Fix (`64a3f0d`):** the docker adapter captures that event's detail and classifies on it (or the exception cause chain), plus a self-diagnosing log. Local mode was always correct (left byte-for-byte unchanged). **Lesson: Task-0 verify-don't-assume must capture errors on the path the feature actually runs (docker/container), not the convenient host-direct path where the message stays intact.**

**Live `make proxy-budget-demo` PASSED:** proxy ON + docker + cap `$0.001` → terminal `over_budget`, no ship, **`budget_tasks=0`** throughout (the distinguishing proof vs P1.2's `budget-demo` — the *mid-loop proxy cutoff*, not the between-steps gate). ## 2. The immediate next step — P1.5 (the multi-node cyclic loop)

### What it is / why (from the §17 Tvashtr-5 Phase-1 decomposition + the glossary)
P1.5 is the **generic Control-Plane executor running a graph-driven, *cyclic* team** — the leap from today's hardcoded 2-node `PM → Engineer` line to an **authored team graph** the executor walks, with **termination** (the loop runs until a condition is met, not a fixed sequence). It is built **graph-driven against a still-hardcoded team-builder** + a simply-persisted canonical idea — the **generic executor + hardcoded builder** split is deliberate: it proves M1 now while keeping Phase-2 composability intact (the Supervisor, P1.8, later swaps the *builder*, never the *executor*). The loop defines the team topology the Supervisor must eventually learn to draft, which is why it comes first.

### This is the visible-feature step
Everything since P0.5 has been backend/plumbing with no UI to smoke-test (the operator flagged this as why the work *felt* unproductive — Tvashtr-9). P1.5 changes that: a real **multi-node cyclic graph on the canvas**, live per-node status through the loop, and the **Tasks-for-Human drawer** (the §15 item whose trigger is exactly P1.5). The 3-way loop (Claude builds the prompt → architect audits the disk → **operator eyeballs the live canvas**) returns to full force; the visual/UX quality bar (**n8n-level or better**, expressed in the DS calm vocabulary — no infinite marching-dash loops) is back as part of acceptance.
