## 5. P1.3b — the two proofs + the flip (design before the brief)
**Goal:** prove the container is a *real* boundary (not the band-aid), then make it the default. Three pieces:

### (a) Crash-resume over the container — the crux
The coarse `@DBOS.step` agent run now spans a **container**. In docker mode `engineer_run_step` does: **reap-before-start → `with DockerWorkspace(...)` (starts `agent-server-<uuid>`, `-p 8010:8000`, `--rm`, ~3s bring-up) → run → pull → `__exit__` (docker stop → `--rm` removes).** A `kill -9` **mid-run skips `__exit__`**, so the container is **ORPHANED** (keeps running — `--rm` only removes on stop). On the next process DBOS recovers the run → the **boot sweep** (lifespan, docker mode) reaps the orphan and frees port 8010 → recovery re-runs the step → **reap-before-start** (a backstop) → a **fresh** container → ships (idempotent, `ship-{run_id}` tag-dedup'd). The attempt-pid log (`engineer_run_attempts`) shows 2 distinct pids; outcome is **exactly-once** — same as Decision 1 (§17), now over a container.
- **What this proves that P1.3a couldn't:** the orphan is actually reaped (the `ancestor=<tag>` filter really matches a running container — the smoke's reap found *nothing*, so this is the **first** time we reap a real orphan), the fresh container starts on the freed port, and exactly-once-ship survives the container lifecycle. *(Cheap de-risk before the full crash dance: start a container, confirm `docker_runtime.list_agent_containers()` finds it and `reap_agent_containers()` removes it — extend `docker_smoke.py`.)*
- **Harness:** the existing `make skeleton-crash` (`scripts/skeleton_crash_demo.sh`) uses a **real** uvicorn `process1 → kill-9 → process2` (NOT the in-process TestClient) and times the kill via "poll `run_events` until the first event, then kill" (the agent is mid-step). For docker it needs **`TVASHTR_AGENT_SANDBOX=docker` exported to BOTH processes** (→ likely a `make skeleton-crash-docker` target) and the kill-timing still works (on_event streams over the WS, proven). Mind the ~3s bring-up before the first event.

### (b) Forced-escape containment — the inverse of P0.4b
P0.4b *demonstrated* the escape: in local mode the agent wrote `/greeting.txt` to the **host** (`backend/greeting.txt` leaked). In docker mode the same absolute write lands **inside the container** (no bind-mount; the pull only reads `/workspace`; the container is torn down) — structurally contained. The proof: **force** the agent to attempt an escape, then **assert the host is clean**.
- **Design questions to settle:** (1) **how to force the attempt deterministically** — the DQ3 reframe tells the agent to write *relative*, so the containment demo needs a *different*, escape-attempting instruction (a crafted/"malicious" PRD or a test-only instruction that says write to an absolute/traversal path); (2) **what paths** — container-absolute `/escape.txt`, path-traversal `../../../escape.txt`, maybe a host-style path that wouldn't exist in the container; (3) **what to assert clean** — the host workspace's parent, the repo root, `backend/`, `/tmp` — wherever a real escape would land; (4) it needs real container + LLM → **operator live-run** (`make containment-demo`). The clean story is a **before/after**: the same attempt leaks on local (P0.4b) but is contained on docker.

### (c) Flip the default to `docker`
One line in `config.py` (`agent_sandbox_mode` default `"local"` → `"docker"`) **after (a)+(b) pass.** **Design nuance to weigh with the operator:** flipping the *global* default means every dev run (incl. `skeleton-run`/`hitl-demo`/`budget-demo`) now spins the heavy agent-server container (~3s + VSCode/VNC overhead) for trivial tasks that don't need containment until P1.5's real-code loop. A clean resolution: **default = `docker` (safety-by-default, like the $5 cap), but keep the fast dev demos explicitly `TVASHTR_AGENT_SANDBOX=local`** (they test orchestration, not containment), while the docker path is exercised by `skeleton-run-docker` + the crash/containment-docker targets. Decide whether to flip now or at P1.5.

### THE BUILD LOOP (how we work — read `.claude/skills/tvashtr-loop/SKILL.md`)
- Build via **`/tvashtr-loop <brief-path>`**: the loop branches → implements → offline gates (`make test`/`lint`, `npm run build`/`test`) → **Playwright MCP** functional gate (if UI) → an **independent review pass** → commits on a **branch** (never merges) → returns a report with a **decision ledger**.

## 7. Open risks & carried items (PROJECTPLAN §13 + the §15 register)
- **⚠️ Write-escape: containment is built but not yet PROVEN over the container — P1.3b proves it.** The container *should* contain the P0.4b escape (structural: no bind-mount), but the forced-escape demo (§5b) is what confirms it. Until then, the band-aid prompt instruction is still the only *demonstrated* mitigation; treat real-code execution as still-unsafe until P1.3b passes + the default flips.
- **The `ancestor=<tag>` reaping is unproven against a real orphan** (the smoke's reap found nothing). The crash test (§5a) is the proof; if the filter doesn't match the running container, orphans wouldn't be reaped and port 8010 would stay held. **De-risk it cheaply first** (start a container, confirm `list_agent_containers` sees it).
- **Image-based reaping is all-or-nothing** (no per-run targeting) — fine for serial single-operator, **breaks under concurrency** (parallel agent runs would clobber each other's containers). Registered §15 (dynamic ports + per-run targeting); the trigger is **P1.5's parallel nodes** or multi-project.
- **The boot-sweep-before-DBOS-recovery ordering is asserted, not proven** (P1.3a). Reap-before-start is a backstop, so the crash test should pass regardless — but watch whether the orphan is reaped by the sweep vs. the backstop.
- **Image version skew** — `latest-python` banners SDK **1.28.0** while the host pins **1.28.1**; the REST/WS protocol worked across it, but the moving tag hurts reproducibility (§15: pin a digest).
- **Budget enforcement is reactive / between-steps (P1.2, by design):** a breach can overshoot ~one step's spend; the agent's own mid-step spend can't be interrupted until **P1.4 (the LiteLLM proxy)**.
- **Other carried items (registered §15):** the `bash_events`/`conversations` **scaffolding denylist is pragmatic and brittle** (a new tool/SDK store, or a real deliverable under `conversations/…`, would defeat it — the principled fix is relocating the server's stores out of the workspace); the FE component/lifecycle-tests gap (vitest is pure-function only); the per-run resolve-suppression edge; the cancelled-gate blocked-`recv` lingering up to 3600s; verbose run-event payloads; **`backend/.tvashtr_workspaces/<run_id>/` accumulates with no GC**; in dev **DBOS resumes abandoned `running`/PENDING runs on every backend boot** (the M0 property + why the kill switch exists — and the cause of the §3.2 zombie).
- **Named upgrades parked in §15 (do NOT drop — operator-flagged):** agent-native resume (reconnect to a surviving container instead of restarting — its enabler now exists: P1.3a's container outlives the kill-9'd client); relocate the Agent Server event stores; pin the image digest; per-run container targeting + ephemeral ports; per-run sandbox-mode observability; per-project budget cap; cost-threshold alert; richer budget-breach resolution; the **LiteLLM proxy (P1.4)**; **section-level** then **CRDT/Yjs** doc locks; **WebSocket (P1.6)**; the **Tasks-for-Human drawer (P1.5)**; FE component tests; workspace GC.
