## Gotchas learned / reinforced this session
- **The parallel-split contract-pin.** When two sessions build the two sides of ONE wire (backend emits / frontend reads) without seeing each other, write the exact JSON contract VERBATIM into BOTH briefs, then verify the two sides match byte-for-byte on disk. This is the one real risk of a seam-split; pinning + verifying neutralizes it. It held perfectly this time (B's `api.ts` types byte-mirrored A's `routers.py` emit).
- **The FF merge's own file list IS the invariant proof.** When A FF-merged, the printed 19-file list (all backend) was the "no frontend touched" proof; B's cherry-pick 11-file list (all `frontend/`) was the mirror. No separate `--name-only` diff needed.
- **A worktree session's files are OUTSIDE the architect's readable paths.** So the worktree session's CONTENT audit happens POST-cherry-pick (once its files land in the main checkout). Confirm its FILE-SET first via `git show --stat <sha> | cat`, then audit content after the pick.
- **`/mnt/user-data/uploads` is READ-ONLY.** The `mv pre-image → /tmp/pre` cache-clear trick can't remove the source — but a fresh `copy_file_user_to_claude` still fetched the post-run version (the stale read-only copy didn't poison it). To diff post-run vs pre-image: stash the pre-image in `/tmp/pre`, re-copy the post-run file, `diff`.
- **The Filesystem MCP can hang (~4-min timeouts).** It did twice this session mid-edit. On a hang: do NOT blindly re-run an edit (it may have half-applied) — when the MCP is back, RE-READ to check state first (the edit either applied or didn't; grep for a marker), then proceed. The operator restarts it by fully quitting + reopening the Claude Desktop app.
- **Seam-split merge order.** The migration-adder (A) FF-merges FIRST; the worktree session (B) cherry-picks onto the result (it diverged off the same base → won't FF; disjoint files → clean). B's branch then needs `git branch -D` (force) — the cherry-pick gave it a new sha, so git doesn't see the original as merged, but the content IS in main.
- **Reproduce-first that isolates the fix line.** A's headline test kept the column/signature scaffolding constant and flipped ONLY the sink's WHERE-clause `(run_id,seq)`→`(run_id,invocation_id,seq)` to go RED→GREEN — proving that exact clause is load-bearing. Stronger than a naive reproduce-first.
