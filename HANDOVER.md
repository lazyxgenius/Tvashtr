- **The Filesystem MCP is intermittently unresponsive** (per prior sessions) — a `write_file`/`edit_file` can silently fail (the "no result received" error); after a restart, verify with a `list`/`read` before assuming it landed.
- **`PROJECTPLAN.md` is ~430 KB with a single enormous line-6 header** (a rolling "Last updated" summary — each new entry PREPENDS its own bolded summary before a `_Prior:_` separator, so the whole history accumulates on that one line). Copy it to the container (`copy_file_user_to_claude`) then `grep -nE '^#{2,3} '`/`sed -n` for section reads. **Editing the header:** `Filesystem:edit_file` DOES match a short, unique substring anchored at the *start* of the giant line (not just whole-line) — anchor on `> **Last updated:** <date> — **Tvashtr-N — <first clause>...floors X backend / Y vitest.**` (stop the oldText right after that first bolded sentence) and insert your new entry + a `_Prior:_` separator before it; you don't need to touch the rest of the line. The dry-run diff comes back huge (expected, single-line diff) — verify success via `hunk count == 2` / grepping the added `+` line in the stored tool-result JSON, not by reading the rendered diff. §17 appends go immediately before `## 18. Glossary`; §15 register items go under the relevant `### Deferred refinements` subsection (anchor on the category header + first bullet).
- **`copy_file_user_to_claude` caches by basename** — re-copying a CHANGED file returns the stale copy. For fresh reads of files CC just changed, use `read_multiple_files`/`read_text_file`. (Unchanged files are safe to re-copy.) Loose git objects are exempt from this concern since each sha is a unique filename.
- **Container filesystem** (`bash_tool`, e.g. `/home/claude/`, `/mnt/user-data/uploads/`) **and the operator's disk** (Filesystem MCP at `/Users/adimac/Desktop/Tvashtr`) **are entirely separate** — `bash_tool` cannot read `/Users/…` paths directly; everything crosses via `copy_file_user_to_claude` (one file per call) or `Filesystem:read_*`.
- **Makefile** must always be edited surgically (never `write_file`) — TAB-indented recipes are fragile to full rewrites.
